4. 데이터베이스 vs 데이터베이서 관리 시스템(Database Mangement System, DBMS)
	1) 데이터베이스(Database: DB)
		- 개인, 회사, 관공서 등에서 업무적으로 필요한 데이터 의미
		ex. 사원정보 (사원 DB)
			 부서정보 (부서 DB)
			 학생정보 (학생 DB)
			 
	2) 데이터베이서 관리 시스템(Database Mangement System, DBMS)
	
		- 데이터베이스 (DB)를 전문적이고 효율적으로 관리하기 위한 S/W.
		ex. MySQL, Oracle, MY-SQL, DB2, ...
		
		- 관리방법?
		  SQL(Structured Query Language)문 이용. (DBMS 언어)
		  
		  SQL문 종류
		  
		  가. DML (데이터 조작어, Data Manipulation Language)
				- INSERT ( 데이터 생성 )
				- DELETE ( 데이터 삭제 )
				- UPDATE ( 데이터 수정 )
				
		  나. DDL ( 데이터 정의어, Data Definiton Language)
				- CREATE 	( 테이블 생성 )
				- ALTER		( 테이블 수정 )
				- DROP 		( 테이블 삭제 )
				- TRUNCATE	( 테이블 절삭 )
				
		  다. TCL ( 트랜잭션 관리, Transaction Control Language )
				DTL ( Data Transaction Language )
				- COMMIT		( 트랜잭션 확정 )
				- ROLLBACK	( 트랜잭션 취소)
			
			==> DML과 연관이 있음
				
		  라. DQL ( Data Query Language )				
				- SELECT 	( 데이터 조회 )
		  
		////////////////////////////////////
		CRUD 작업?
			
			Create : 생성 ( INSERT 작업 의미 )
			Read	 : 조회 ( SELECT 작업 의미 )
			Update : 수정 ( UPDATE 작업 의미 )
			Delete : 삭제 ( DELETE 작업 의미 )		
		
		////////////////////////////////////
		
		- DBMS가 DB를 관리하는 방법
		  가. 관계형 DB
		  나. 계층형 DB
		  다. 망형 DB
		  라. 객체지향 DB
		  ...
		
5. 관계형 데이터 베이스 ( Relational DataBase :  RDB )

	1) 개념
		- 행(레코드) / 열(컬럼)로 구성된 2차원 테이블 형태를 가짐.
		- 여러 테이블간에 특정 연결고리를 이용해서 관계를 맺어서 관리됨.
	2) 종류
		ex. MySQL, Oracle, MY-SQL, DB2, ...
		
	3) 현업에서 RDB 대립되는 데이터 구조를 가진 형태: 
		NoSQL ( Not only SQL, 비정형 데이터 ,{key:value} 구조 )
		ex. MongoDB, Casandra
		
6. SQL ( Structured Query Language )
	
	1) 개요
	 - RDB에서 사용하는 언어.
	 - 식별자로 구성 ( 예약어 및 사용자 지정 식별자(ex. 테이블명, 컬럼명) 가능 )
	 - 대소문자 구별 안됨 ( SElECT와 select 동일 )
	 - MySQL에서는 데이터 대소문자 구별안함 ( 'A'와 'a' 동일 )
		Oracle에서는 데이터 대소문자 구별함 ( 'A'와 'a' 다름)
	 - 자바에서는 문자와 문자열을 구별했음. ( 'A', "ABC" )
		SQL에서는 문자와 문자열을 구별안함. ( 'A', 'ABC', '2026-04-14' )
		""는 별칭 (alias)에서만 사용하자.
	 - 산술 연산자 및 연산자 
	 - 함수( 자바의 method )
	 - 조건문
	 
	2) SQL 종류 ( RDB 종류에 따라서 )
		
		가. 표준화된 SQL문 ( 독립적인 SQL문, ANSI SQL )
			- 모든 RDBMS에서 사용 가능

		나. 벤더(업체)에 의존적인 SQL문
			- MySQL에서만 사용
			  Oracle에서만 사용
			- 함수에서 주로 차이가 있음.
			
	2) SQL문 종류2 ( 기능에 따라서)
	
		가. DML ( Data Manipulation Language )
			- insert
			- update
			- delete
		나. DDL ( Data Definition Language )
			- creat
			- alter
			- drop
			- truncate
		다. DQL ( Data Query Language )
			- select
		라. TCL(DTL) ( Transaction Control Language, Data Transaction  Language )
			- commit
			- rollback

8. null 값
	
	1) 개념
		- 테이블의 컬럼에 값이 없음. 
		- select 하면 비워져서 보임.
		
	2) 특징
		- 기본적으로 모든 컬럼은 null값을 가질 수 있음.
		  강제적으로 null값을 허용하지 않도록 설정할 수 도 있음. (NOT NULL 제약조건)
		
		- null 값을 가진 컬럼을 연산하면 결과는 null이 나온다 (**********) // [회고파트] 이게 왜 중요한지 찾아볼것
		- null값을 임의의 기본값으로 변경하자
		  
		- ifnull(컬럼명, 기본값) ==> 컬럼명이 null일때 기본값으로 치환됨.
											  oracle에서는 NVL(컬럼명, 기본값)		
											  
		- is null: null값 찾기
		- is not null: null이 아닌 값 찾기
		
		- 정렬시 null값은 최소값으로 처리함(MySQL / oracle -> 최대값으로 처리함)
		
		
9. 제약조건 ( Constraints ) - 외우기	// [오늘 핵심내용]
	
	- 목적: 무결성 보장하는 방법
	- 컬럼단위로 지정
	
	1) primary key ( PK )
		- 기본키 제약조건
		- 지정된 컬럼은 반드시 값을가져야 되고, 유일한 값(중복x)
		- 테이블 당 한개씩 지정 가능
		- 용도: 레코드 식별
				ex. emp 	PK: empno 
					 dept PK: deptno
		- 복합컬럼 가능
		(다른 테이블의 PK들로 이루어진 복합 PK도 설정은 가능 but 대부분은 복합PK대신 PK들의 조합을 넘버링을 한 컬럼을 PK로 사용한다.)
		- 자동으로 index 생성됨. (ex. 책의 색인표 역할)
		  index이용하면 원하는 레코드를 빨리 찾을 수 있다.
		  index남용은 내부 정렬과 B트리 작업의 추가로 인해 성능 저하가 발생할 수 있다.
		
	2) unique
		- 유니크 제약조건
		- 지정된 컬럼은 반드시 유일한 값을 가진다
		  단. null값은 허용 ==> 중복x, null 허용
		- 테이블당 여러개 지정 가능
		- 복합컬럼 가능
		- 자동으로 index 생성됨
		
	3) check	
		- 비즈니스 로직 관련 제약조건임
		- 자바 프로그램으로도 대체 가능
		ex. 
			성별값: 남자/여자
						남/여
						F/M	<==== 이 값만 사용하도록 강제하는 check 제약조건을 지정.
						Female/male
						1/0
			중학생학년
			1학년/ 2학년/ 3학년 <==== 이것만 가능하도록 check 제약조건을 지정.
			4학년 
			
	4) foreign key
		- 참조키 또는 외래키 제약조건
		- 조인(join)할 때 사용됨.
		
		ex. 
						emp ( slave 테이블)							dept ( master 테이블 )
	---------------------------------------- 			-------------------------
	empno(PK) | ename | ... | sal | deptno(fk) 		deptno(PK) | dname | loc
	----------------------------------------			-------------------------
	7369	  		SMITH			 800	 	20						  10	  RESEARCH  NEW YORK
	7869	  		John			 1500		20	------------->   20	  SALRES
												50 (X)				  30
												null (O)				  40

			가. master테이블의 컬럼중에서 pk또는 unique 컬럼나 참조할 수 있음 
				 // 외래키는 -> 유일성을 만족하는 키를 참조가능하다?
			나. fk컬럼이 가질 수 있는 컬럼값은 master에서 참조하는 컬럼(PK, unique)의 값 또는 null값만 가질 수 있음.
		- master의 컬럼명과 fk 컬럼명은 서로 달라도 무관 ( 권장은 동일하게 지정 )

10. select + 조건식 지정
	
	1) 개념
		조건에 일치하는 레코드만 조회 ( selection 기증 )
		
	2) 문법
	
		select	: 컬럼(속성, 릴레이션 스키마)
		from		: 테이블명
		where 	: 조건식
		
		실행순서:
			from > where > select 절
			
	3) 조건식에 사용가능한 연산자?
		
		가. 비교연산자
			= 	: 일치	( 자바의 == )
			!=	: 불일치
			>	: 큰가
			>=	: 크거나 같은가
			<	: 작은가
			<=	: 작거나 같은가
			
			ex. select *				# 3번
				 from emp				# 1번
				 where sal = 1000;	# 2번
	
				 where sal > 1000;
				 where sal <= 1000;
				 where sal != 1000;
				 
				 where ename = 'SMITH';	//""도 가능은 하지만 ANSI를 따르는 것을 권장(oracle에서는 항상 ''만 사용)
				 where ename = 'smith';	// MySQL은 대소문자 구분X (oracle에서는 대소문자를 따로 구별한다)
												// Oracle은 테이블, 컬러명은 소문자도 대문자로 저장
												// 값만 대소문자를 구별
												
				 where hiredate = '1980-12-17'; // 날짜데이터는 ''지정
				 where hiredate > '1980-12-17'; // 날짜데이터는 내부적으로 숫자로 관리되기때문에 비교가능
				 
	나. 범위 연산자
		
		- between A and B : A와 B 범위에 존재하는 값.(A,B 포함)
			
			ex. 	select *				
					from emp				
					where sal between 1000 and 2000;	
					where hiredate between '1980-12-17' and '1984-12-17';
	
	다. 여러개 지정
		
		IN ( 값1, 값2, 값3, ... )
	
			ex. 	select *				
					from emp				
					where sal IN (1000,2000,800);	
					
					where ename IN ('SMITH','FORD');
					where hiredate IN ('1981-12-03','1980-12-19');
	
	라. null 찾기
	
		is null
		is not null
		
		ex. 	select *				
				from emp	
				where comm is null;		// null 찾음
				whrer comm is not null;	// null이 아닌거 찾기
				
	마. litke 연산자
		
		- 패턴으로 조회 
		
		- 와일드카드 (패턴)
			
			가. %	: 없거나 여러개 값으로 치환
			
			나. _ ( 언더바 ) : 반드시 하나의 값으로 치환
		
		ex. 	select *				
				from emp	
				where ename like '%A%';	// A앞뒤로 어떤 문자든 와도 상관없다. 없어도 상관없다.
				where ename like 'A%';	// A로 시작하는 이름
				where ename like '%A';	// A로 끝나는는 이름.
				
				where ename liek '_A';	// 2글자이고 A로 끝나는 이름
				whree ename like '___A%'; // 네번째 글자가 A인 이름
				
	바. 논리연산자
			
			and : 그리고
			or  : 또는
			not : 부정
			
			ex. ename이 SMITH 이고 sal가 10000보다 큰 사원?
				: where ename = 'SMITH' and sal > 1000;
				
				 ename이 SMITH 이거나 sal가 10000보다 큰 사원?
				 : where enams = 'SMITH' or sal > 1000;
				 
				 ename이 SMITH 아닌 사원?
				 ex. where ename != 'SMITH'
					  where NOT ename = 'SMITH'
					  where NOT sal between 1000 and 2000;
					  where NOT sal IN (1000,2000,800);
					  where NOT ename like '___A%';

			 order by 컬럼명;			// 오름차순
		    order by 컬럼명 asc;	// 오름차순

			 select *
			 from emp
			 order by sal;
			 order by sal asc;
			 order by sal desc;
			 
			 order by hiredate desc; // 신입사원부터

3. ANSI 조인

	1) cross 조인
	
		문법:
			SELECT
			FROM 테이블1 CROSS JOIN 테이블2
			
		동작:
			테이블1의 하나의 레코드와 테이블2의 모든 레코드가 연결된다
			조인된 결과는 데이터로서 사용불가
			최종 레코드는 테이블1 갯수 * 테이블2 갯수 만큼 결과가 출력된다.
			
	2) natural 조인 // inner join에 속한다
	
		문법1:
			SELECT
			FROM 테이블1 NATURAL JOIN 테이블2;
			
		문법2 :
			SELECT [별칭1.]컬럼, [별칭2.]컬럼, ... 
			FROM 테이블1 [별칭1] NATURAL JOIN 테이블2 [별칭2];
			
		동작: 테이블1과 테이블2의 공통컬럼을 찾아서 조인한다.
				만약 공통컬럼이 없다면 조인 불가.
				만약 공통컬럼이 2개라면 쌍으로 비교해서 조인.
		
		단점: 어떤 컬럼으로 조인되었는지 추가로 확인하는 작업이 필요하다. ( 가독성이 떨어짐 )
				공통컬럼의 존재를 알고 있어야 사용가능하다.
		
		현재 조인조건: natural join
		검색조건: where 절
		
		문법3:
			SELECT [별칭1.]컬럼, [별칭2.]컬럼, ... 
			FROM 테이블1 [별칭1] NATURAL JOIN 테이블2 [별칭2]
			WHERE ;
			
	3) USING 절 // inner join에 속한다
					
		문법:
			SELECT [별칭1.]컬럼, [별칭2.]컬럼, ... 
			FROM 테이블1 [별칭1] NATURAL JOIN 테이블2 [별칭2] USING(공통컬럼)
			// (join_colum_list), USING에서는 별칭 사용 불가
			[WHERE]
			[GROUP BY]
			[HAVING]
			[ODER BY]
		
		동작:
			테이블1과 테이블2에서 USING에 설정된 공통컬럼으로 조인한다.
		
		특징:
			별칭을 사용해 컬럼을 호출할 경우 에러가 발생한다.	//[알아볼것]: sql에서 별칭으로 컬럼에 접근하는 방법
			컬럼명이 같을때 사용가능
			
	4) ON 절 ( 범용적 )
		
		문법:
			SELECT [별칭1.]컬럼, [별칭2.]컬럼, ... 
			FROM 테이블1 [별칭1] NATURAL JOIN 테이블2 [별칭2] ON 조건
			// ON에서 조건으로 사용한 컬럼은 SELECT 절에서 테이블을 지정해야한다.
			[WHERE]
			[GROUP BY]
			[HAVING]
			[ODER BY]
			
		ex.
			SELECT ename, sal, dname, loc, e.deptno	--	공통 컬럼의 소속 지정
			FROM emp e JOIN dept d ON e.deptno  = d.deptno;	-- equi조인
			
		특징:
			ON에서 조건식이 명시되므로 가독성이 높아진다.
			조건식으로 컬럼이 필터링 되므로 컬럼명이 달라도 조인이 가능하다.
			
			
		# non-equi조인
		
		ex. emp와 salgrade
		
			SELECT *
			FROM emp e JOIN salgrade s ON e.sal BETWEEN s.losal AND	s.hisal;
			
		# 3개 조인
		
			a. NATURAL JOIN	// 3개의 테이블에 공통된 컬럼이 존재해야한다.
			
			ex.
				SELECT *
				FROM t1 NATURAL JOIN t2 
						  NATURAL JOIN t3;					  
			
			b. USING
		
			ex. 
				SELECT *
				FROM t1 JOIN t2 USING(join_colum_list)
						  JOIN t3 USINT(join_colum_list);
			
			c. ON
			ex. 
				SELECT *
				FROM t1 JOIN t2 ON 조건식
						  JOIN t3 ON 조건식;
						  
		ex. 사원명, 부서번호, 부서명, sal, sal등급 출력하시오
		
		SELECT ename, deptno, dname, sal, grad
		FROM emp e JOIN dept USING(deptno)
					  JOIN salgrade s ON e.sal BETWEEN s.losal AND s.hisal;
					  
		SELECT ename, e.deptno, dname, sal, grad
		FROM emp e JOIN dept d ON e.deptno = d.deptno
					  JOIN salgrade s ON e.sal BETWEEN s.losal AND s.hisal;
					  
3. OUTER JOIN
	
	- 기본적으로 JOIN은 INNER를 의미한다 (일치하는 데이터만 출력됨)
	  but, 일치하지 않는 데이터까지 포함해서 조인하는 방식임.
	  
	문법:
	
		SELECT
		FROM t1 { LEFT | RIGHT } [OUTER] JOIN t2 { ON | USING }
		
		- LEFT : t1 레코드는 모두 출력
		- RIGHT: t2 레코드는 모두 출력
		
		# Oracle에서는 LEFT | RIGHT | FULL 3가지 OUTER JOIN 을 지원한다
		
	ex.
		SELECT *
		FROM  emp RIGHT OUTER JOIN dept USING(deptno);
		
		SELECT *
		FROM  emp RIGHT OUTER JOIN dept ON emp.deptno = dept.deptno;	
		
		SELECT *
		FROM  emp e RIGHT OUTER JOIN dept d ON e.deptno = d.deptno;	
		
		--  신입사원
		insert into emp (empno, ename,job,mgr,hiredate,sal,comm,deptno)
		values ( 9000, '홍길동', 'SALESMAN', 7499, NOW(), 700, 0, null );	// deptno -> null : 부서배치 안받음
		commit; 
		
		SELECT *
		FROM  emp e LEFT OUTER JOIN dept d ON e.deptno = d.deptno;
		
		# MySQL에서 누락된 양쪽 테이블 모두 보기
		
		- UNION | UNION ALL ( 중복제거 | 중복포함 ) 
			
		SELECT *
		FROM  emp e LEFT OUTER JOIN dept d ON e.deptno = d.deptno
		
		UNION 
		
		SELECT *
		FROM  emp e RIGHT OUTER JOIN dept d ON e.deptno = d.deptno;
		
		// 하나의 문장이다.

5. 서브쿼리( subquery )	
	
	1) 개념
		원하는 데이터를 한 번의 select만으로 안될때
		여러번의 select문을 사용해서 원하는 결과를 얻음.
		
	ex. SMITH 사원보다 더 많은 sal을 받는 사원 출력
	
		작업1 > SELECT 사원의 sal 검색 -> 800 가정
				  
				SELECT sal
				FROM emp
				WHERE ename = 'SMITH';
				  
		작업1 > SELECT empno, ename, sal
				  FROM emp
				  WHERE sal > 800;
				  
		작업1과 작	업1를 합치면 subQuery 문법이 된다
	
		최종 subquery문:
				
				-- 메인쿼리
				SELECT empno, ename, sal
				FROM emp
				WHERE sal > (	-- 서브쿼리
						SELECT sal
						FROM emp
						WHERE ename = 'SMITH');
						
	1) 특징
		- 서브쿼리는 반드시 '()'를 가짐 ( '()'가 없는 SELET이 메인 쿼리 )
		- 서브쿼리가 먼저 실행되고 그 결과값을 이용해서 main query가 실행됨
		- 서브쿼리가 사용가능한 위치는 거의 모든곳에서 사요이 가능
		  ex. WHERE, HAVING, FROM, INSERT, DELETE, UPDATE, CREATE, ...
		  
	ex1. emp테이블에서 사원번호가 7521 의 업무와 동일하고 급여가 7934보다 많은 사원의 정보(사원번호,이름,job,hiredate,sal)출력?
	
		SELECT empno, job, hiredate, sal 
		FROM emp
		WHERE 
		job = ( SELECT job
				  FROM emp
				  WHERE empno = 7521)
		AND
		sal > ( SELECT sal
				  FROM emp
				  WHERE empno = '7934');
				  
	ex2. emp테이블에서 급여의 평균보다 적은 급여를 받는 사원 정보 출력(사원번호,이름,job,hiredate,sal)?
		
		SELECT empno, ename, job, hiredate,sal
		FROM emp
		WHERE 
		sal < ( SELECT AVG(sal)
				  FROM emp);
				  
				  
	ex3.  emp테이블에서 20번 부서의 최소급여보다 많은 모든 부서를 출력? (부서명, 최소급여)

		SELECT deptno, dname, min(sal)
		FROM emp e JOIN dept d USING(deptno)
		GROUP BY deptno
		HAVING min(sal) > (
			SELECT min(sal)
			FROM emp
			WHERE deptno = 20);
	
	3) 연산자
		
		가. 단일행 연산자
			
			- 서브쿼리가 실행된 후 하나의 행(단일행)이 리턴하는 경우에 사용
			- 비교연산자 (=, > , >= , <, <=)
		
		나. 복수행 연산자	//[회고 point] any,all 키워드와 min, max 중에 처리속도의 차이에 중점을 둔 장단첨 
			
			- 서브쿼리가 실행된 후 여러 행(복수행)이 리턴하는 경우에 사용
			- IN, ANY, ALL EXISTS
			
			- ANY: 서브쿼리 결과 중에 하나라도 만족하는 경우 [최소값보다 클때, 최대값보다 작을때]
				ex. 
					최소값보다 큰	: < ANY()	<==>	SELECT MAX()
					최대값보다 작은: > ANY()	<==>	SELECT MIN()
					
			- ALL: 서브쿼리 결과의 모든 값을 만족하는 경우 [최소값보다 작은, 최대값보다 큰]
				ex. 
					최소값보다 작은: < ALL()	<==>	SELECT MIN()
					최대값보다 큰	: > ALL()	<==>	SELECT MAX()
			
	
			ex1. emp테이블에서 업무별로 최소급여를 받는 사원정보 출력(사원번호,이름,job,hiredate,sal)
			
				SELECT empno, ename, job, hiredate, sal 
				FROM emp
				WHERE sal IN (
					SELECT min(sal)
					FROM emp
					GROUP BY job);
				
			ex2. emp 테이블에서 job이 manager인 사원의 최소급여보다 적은 급여를 받는 사원 정보 (사원번호,이름,job,hiredate,sal)			
	
				SELECT empno, ename, job, hiredate, sal
				FROM emp
				WHERE sal < (
					SELECT min(sal)
					FROM emp
					WHERE job = 'MANAGER');
				
			# 최소값보다 작은
			
				SELECT empno, ename, job, hiredate, sal
				FROM emp
				WHERE sal < ALL (		// All 내부 서브쿼리의 결과의 모든 값보다 작은 값
					SELECT sal
					FROM emp
					WHERE job = 'MANAGER');		
			
				  
			ex3. emp 테이블에서 job이 manager인 사원의 최소보다 많은 급여를 받는 사원 정보 (사원번호,이름,job,hiredate,sal)				  
				  
				SELECT empno, ename, job, hiredate, sal
				FROM emp
				WHERE sal > (
					SELECT MIN(sal)
					FROM emp
					WHERE job = 'MANAGER');
				
			# 최소값보다 많은: 서브쿼리 결과 중에 하나라도 만족하면 (이때 하나 == 최소값) 
			
				SELECT empno, ename, job, hiredate, sal
				FROM emp
				WHERE sal > ANY (
					SELECT MAX(sal)
					FROM emp
					WHERE job = 'MANAGER');
				
				
			ex4. emp 테이블에서 job이 manager인 사원의 최대급여보다 적은 급여를 받는 사원 정보 (사원번호,이름,job,hiredate,sal)				  
				
				SELECT empno, ename, job, hiredate, sal
				FROM emp
				WHERE sal < (
					SELECT MAX(sal)
					FROM emp
					WHERE job = 'MANAGER');				
				
			 # 최대값보다 적은: 서브쿼리 결과 중에 하나라도 만족하면 (이때 하나 == 최대값) 
			 
				SELECT empno, ename, job, hiredate, sal
				FROM emp
				WHERE sal < (
					SELECT sal
					FROM emp
					WHERE job = 'MANAGER');
				
				  
			ex5. emp 테이블에서 job이 manager인 사원의 최대급여보다 많은 급여를 받는 사원 정보 (사원번호,이름,job,hiredate,sal)				  
				  
				SELECT empno, ename, job, hiredate, sal
				FROM emp
				WHERE sal > (
					SELECT MAX(sal)
					FROM emp
					WHERE job = 'MANAGER');
				
			# 최대값보다 큰
			
				SELECT empno, ename, job, hiredate, sal
				FROM emp
				WHERE sal > ALL (
					SELECT sal
					FROM emp
					WHERE job = 'MANAGER');
			
			
	4) exists 연산자
	
		문법:
				SELECT 
				FROM
				WHERE EXISTS (서브쿼리);
				
		동작: 서브쿼리 실행결과에 따라 main query가 실행된다 
				결과가 없다면 main query는 실행되지 않음
				
		ex.
			SELECT *
			FROM emp
			WHERE EXISTS (
				SELECT ename
				FROM emp
				WHERE sal = 800);

6. 인라인뷰 (inline-view)
	
	- 개념: 
			SELECT
			FROM (서브쿼리) <== 서브쿼리
		
	- 목적: 성능향상
	
	ex. emp와 dept테이블에서 부서별 sal총합과 평균을 출력?

			select e.deptno, sum(sal), round(avg(sal)), count(*)

			group by deptno 
			
			emp:  15개, dept: 4개

			SELECT e.deptno, total_sum, total_avg, cnt
			FROM ( 
				SELECT deptno, SUM(sal), total_sum, ROUND(AVG(sal)), total_avg, COUNT(*) cnt
				FROM emp
				GROUP BY deptno) e JOIN dept d ON e.deptno = d.deptno; 
			
			인라인: 4개, dept: 4개

2. 트랜잭션(transaction)

	1) 개념:
		1개 이상의 DML 작업들을 논리적으로 하나의 작업으로 묶어서 처리하는 개념으로, 묶음을 의미한다.
	
		ex. 
			계좌이체	(A에서 B로 500 이체)
			1. A계좌에서는 update (1000 -> 500)
			2. B계좌에서는 insert (null -> 500)
			
			1,2 두가지를 하나의 트랜잭션으로 두 동작 모두 성공했을때만 적용, 하나라도 실패하면 취소
			
			# 현재상황
			A 계좌								B 계좌
			1000
						
			# 성공
			A 계좌								B 계좌
			500									500
			
			# 실패
			A 계좌								B 계좌
			1000
			
	2) 트랜잭션 명령어 (TCL, DTL)
			
		가. commit
			- 트랝개션이 모두 성공했을 때 실제로 반영하는 명령어
			
		나. rollback
			- 트랜잭션이 하나라도 실패했을 때 실제로 모든 작업을 취소하는 명령어
			
	3) 특징
		- 시작 ~ 종료
		  시작은 DML을 사용하면 자동으로 시작됨
		  
		  ex.
		  
						<---- 트랜잭션 시작
				insert
				delete
				...
						<---- 트랜잭션 종료(commit, rollback)
						
	4) DBMS마다 트랜잭션 처리방법이 다름
	
		가. MySQL
			- auto commit으로 처리됨
			  따라서 트랜잭션으로 묶을 수 없음.
			- auto commit 비활성화해서 트랜잭션으로 처리 가능
				
				# autocommit 여부 확인
				show variables like 'autocommit%';
				
				# autocommit 비활성화
				set autocommit = false;
			
		나. Oracle
			- 명시적으로 commit/ rollback으로 트랜잭션을 종료해야 됨.

3. INSERT
	
	1) 용도
		- 새로운 레코드 생성
		- 단일행 생성 및 다중행 생성
		
	2) 단일행 생성 방법
		
		가. 컬럼명 명시
			
			문법: 
				// 트랜잭션 시작
				insert into 테이블명 (컬럼명, 컬럼며2, ...) values(값,값2,...);
				// 트랜잭션 종료 ( commit / rollback )
					
			특징:
				- 선택적으로 임의 컬럼에 값을 저장할 수 있다.
				- 지정하지 않은 컬럼에는 null 값이 저장된다. (지정되지 않은 컬럼은 not null 제약조건이 없어야 한다)
				- 컬럼명이 명시되기 때문에 가독성이 높다.
		
		나. 컬럼명 생략
			
			문법:
				insert into 테이블명 values (값, 값2, ... );
				
			특징:
				- 선택적으로 컬럼을 지정하지 않기 때문에 테이블의 컬럼 순서대로 값이 저장된다.
				- 반드시 테이블의 모든 컬럼에 값을 지정해 줘야 한다. ( 특정 컬럼 생략 불가 )
				- null 입력은 가능함
				- 컬럼명이 명시되지 않기 때문에 가독성이 낮음.
				
		다. 주의사항
			- 제약조건을 신경써야 한다.
			  Primary Key	: 반드시 값을 가지고 중복되지 않도록
			  Unique			: 유일한 값 저장
			  not null		: 반드시 값 저장.
			  
	3) 다중행 생성
		
		가. 서브쿼리 용

				///////////////////////////

				from 테이블명

				ex. 
					create table my_emp
					as

		나. value list 이용
		
			문법:
				insert into 테이블명( 컬럼명,... )

						 (값, 값2, ... ),
						 (값, 값2, ... ),

			ex.
				insert into my_emp(empno, ename, sal)

6. DDL(Data Definition language: 데이터 정의어)
https://docs.oracle.com/cd/E17952_01/mysql-8.0-en/create-table.html

	1) 용도
		
		- 객체(테이블, 인덱스, 사용자, ... )를 생성, 수정, 삭제 할때 사용한다.

	2) 특징
		
		- DDL은 자동으로 commit된다. ( rollback 불가 )
		
	3) 테이블 생성 문법
		
		CREATE [TEMPORARY] TABLE [IF NOT EXISTS] tbl_name
		(col_name  data_type,
		 col_name  data_type 제약조건 <= [NOT NULL | NULL] [DEFAULT {literal | (expr)} ]
													[AUTO_INCREMENT] [UNIQUE [KEY]] [[PRIMARY] KEY]
													FOREIGN KEY reference_definition
													check_constraint_definition
		
		DEFAULT {literal | (expr)} ]
		: INSERT할때 컬럼명을 지정하지 않으면 null 대신에 기본값이 설정됨.
		ex. writeday date DEFAULT now()
		
		AUTO_INCREMENT
		: 컬럼이 숫자인 경우, 값을 지정하지 않아도 숫자가 증가한다. ex) 게시판 넘버링
													
		reference_definition:
			REFERENCES tbl_name (key_part,...)	
			(REFERENCES master테이블 (master컬럼))
			[ON DELETE reference_option]
			[ON UPDATE reference_option]
			
		reference_option:
			RESTRICT | CASCADE | SET NULL | NO ACTION | SET DEFAULT
			
		# CASCADE	: 마스터 테이블의 키를 삭제하면 외래키의 데이터(튜플)도 삭제된다
		# SET NULL	: 마스터 테이블의 키를 삭제하면 슬레이브 테이블의 데이터(속성)가 null로 바뀐다
		// [회고포인트]: 참조 무결성(Referential Integrity)을 유지하기 위한 방법
		
		check_constraint_definition:
			[CONSTRAINT [symbol]] CHECK (expr) [[NOT] ENFORCED]
		# expr(expression) : 수식, 표현
			ex.
				CONSTRAINT CHECK (컬럼명 in ('M','F'))
		
	4) 데이터 타입
		
		가. 수치형
		
				- 정수형:
					tinyint		: (1byte)
					smallint		: (2byte)
					medinumint	: (3byte)
					int(integer): (4byte)
					bigint		: (8byte)
				
				- 실수형
					float
					double
					
		나. 문자형
		
				- char(n) : 글자 갯수 ( Oracle에서는 char(4) => 4byte)
								고정길이 문자형 처리(빈 부분을 공백으로 채움)
					
					ex. char(4): 영문이든 한문이든 4글자 저장가능
						 char(4) <- 'A' ==> 'A   '
				
				- varchar(n) : 글자 갯수 ( Oracle에서는 varchar2(n) => n byte)
									가변길이 분자형 처리(저장되는 크기만큼만 할당)
				
					ex. varchar(4) : 영문이든 한문이든 4글자 저장가능		
						 varchar(4) <- 'A' ==> 'A'
		
		다. 날짜형
		
			date		: 날짜만 저장, insert할때 curdate()
			
			time		: 시간만 저장, insert할때 curtime()
			
			datetime	: 날짜 + 시간, insert할때 now()
			
	# 게시판 테이블 샘플
	
		create table if not exists board
		(
			num int PRIMARY KEY AUTO_INCREMENT,
			title varchar(100) NOT NUlL,
			author varchar(10) NOT NUlL,
			content varchar(500) NOT NUlL,
			writeday datetime DEFAULT now(),
			readcnt int DEFAULT 0
		);
		
6. 테이블에 제약조건 설정방법
	
		1) 테이블 작성하면서 제약조건 설정
		
			- create만 필요
			
			가. 컬럼레벨
				
				- 테이블의 컬럼을 설정하면서 제약조건을 같이 설정
				- 5가지 제약조건 모두 사용 가능
					: Primary key, unique, not null, check, foreign key
				
				문법:
					create table NOT EXITSTS 테이블명
					(	컬럼명 데이터 타입 제약조건,
					...
					);
					
				ex. 
					create table if not exists board
					(
						num int PRIMARY KEY AUTO_INCREMENT,
						title varchar(100) NOT NUlL,
						author varchar(10) UNIQUE,
						content varchar(500) NOT NUlL,
						writeday datetime DEFAULT now(),
						gender char(4) CONSTRAINT CHECK (gender in ('M','F')),
						readcnt int DEFAULT 0
					);		
			
			나. 테이블 레벨
				
				- 테이블의 컬럼들을 모두 설정하고 나중에 제약조건을 설정
				- not null을 제외한 제약조건 사용 가능
					: Primary key, unique, check, foreign key
				
				문법:
					create table NOT EXITSTS 테이블명
					(컬럼명 데이터 타입,
					컬럼명 데이터 타입,
					컬럼명 데이터 타입,
					...,
					제약조건1 (컬럼명),
					제약조건2
					);
					
				ex. 
					create table if not exists board3
					(
						num int AUTO_INCREMENT,
						title varchar(100) NOT NUlL,
						author varchar(10) NOT NUlL,
						content varchar(500) NOT NUlL,
						writeday datetime DEFAULT now(),
						gender char(4),
						readcnt int DEFAULT 0,
						
						CONSTRAINT PRIMARY KEY(num),
						CONSTRAINT CHECK (gender in ('M','F')),
						CONSTRAINT UNIQUE (author)
					);		
		
		2) 테이블 만든후에 나중에 제약조건 설정
		
			- create + alter 필요	
			- alter문 이용한 제약조건 추가
			
			ex. 
				create table if not exists board4
				(
					num int,
					title varchar(100) NOT NUlL,
					author varchar(10) NOT NUlL,
					content varchar(500) NOT NUlL,
					writeday datetime DEFAULT now(),
					gender char(4),
					readcnt int DEFAULT 0
				);				
				
				가. not null 제약조건 변경(modify) 방법
					
					문법:
						alter table 테이블명
						modify add 컬럼명 데이터타입 not null
						
					ex.
						alter table board4
						modify title varchar(100) not null;
				
				나. not null 아닌 나머지 제약조건 추가(add) 방법
				
					문법:
						alter table 테이블명
						add CONSTRAINT 제약조건(컬럼명);		// 테이블 레벨 문법과 동일
					
					ex.
						# modify + add 같이 사용해서 primary key와 auto_increment 한꺼번에 설정
						alter table board4
						modify num INT AUTO_INCREMENT,
						add CONSTRAINT PRIMARY KEY(num);
						
						alter table board4
						add CONSTRAINT CHECK (gender in ('M','F'));
						
						alter table board4
						CONSTRAINT UNIQUE (author);
									
7. foreign key 설정
	
	create table master1
	(no int PRIMARY KEY,
	 name varchar(10) not null);
	 
	insert into master1 (no,name) values(1,'aa1');
	insert into master1 (no,name) values(2,'aa2');
	insert into master1 (no,name) values(3,'aa3');
	
	create table slave1
	(num int PRIMARY KEY,
	 ename varchar(10) not null,
	 no int ,
	 CONSTRAINT FOREIGN KEY(no) REFERENCES master1 (no) ON DELETE CASCADE
	 );
	
	insert into slave1 (num,ename, no) values(10,'slave1',1);
	insert into slave1 (num,ename, no) values(20,'slave2',2);
	insert into slave1 (num,ename, no) values(30,'slave3',3);
	insert into slave1 (num,ename, no) values(40,'slave4',4); -- 에러발생
	-- FOREIGN KEY이기 때문에 마스터 테이블의 key 범위에서 벗어날 수 없다.
	insert into slave1 (num,ename, no) values(50,'slave5',null);
	
	commit;
	
	# master1의 레코드
		
	 delete from master1 where no = 1;
	
	
	create table master2
	(no int PRIMARY KEY,
	 name varchar(10) not null);
	 
	insert into master2 (no,name) values(1,'aa1');
	insert into master2 (no,name) values(2,'aa2');
	insert into master2 (no,name) values(3,'aa3');
	
	
	create table slave2
	(num int PRIMARY KEY,
	 ename varchar(10) not null,
	CONSTRAINT foreign key (no) references master1 (no) on delete set null );
	
	insert into slave2 (num,ename, no) values(10,'slave2',1);	
	insert into slave2 (num,ename, no) values(20,'slave2',2);
	insert into slave2 (num,ename, no) values(30,'slave3',3);
	insert into slave2 (num,ename, no) values(50,'slave5',null);
	
	commit;
	
	
8. 테이블 삭제 및 절삭 (DDL 이기 때문에 rollback 안됨)

	- drop table if exists 테이블명, 테이블명2, ...;
	
	ex. 
		DROP TABLE IF EXISTS board;
		DROP TABLE IF EXISTS board2, board3;

	- trunate table 테이블명; -- 테이블내의 모든 레코드를 삭제
	
	* delete vs trunate
	  
	  - delete	: DML - ROLLBACK 가능
	  - trunate : DDL - ROLLBACK 불가능
	  
9. 테이블 수정
	https://dev.mysql.com/doc/refman/8.0/en/alter-table.html
	
	- 컬럼추가
		
		alter table 테이블명
		add column 컬럼명 데이터타입;
		
	- 컬럼추가
		
		alter table 테이블명
		drop 컬럼명;
		
	- 제약조건추가
		
		alter table 테이블명
		add 제약조건;
		
		alter table 테이블명
		modify 컬럼명 데이터타입 not null;
		
	- 컬럼이름변경
		
		alter table 테이블명
		rename column 컬럼명 to 새컬럼;
		
	ex.
		create table if not exists my_dept
		( no int primary key,
		  name varchar(10)
		);
		
		-- 컬럼 추가
		alter table my_dept
		add column address varchar(20);
		
		-- 컬럼 변경(크기변경)
		alter table my_dept
		add column address varchar(50);
		
		-- 컬럼 변경(크기변경)
		alter table my_dept
		modify address varchar(10);	-- 데이터가 저장되어 있다면 해당 데이터가 유지 가능한 크기를 지정해야된다
		
		-- 컬럼 이름변경
		alter table my_dept
		RENAME COLUMN address to addr;
		
		-- 컬럼 삭제
		alter table my_dept
		drop name;
