1. 리눅스(Linux)
	
	1) 개요
		- 핀란드의 헬싱키 대학교의 리누스 베네딕트 토바즈( Linus Benedict Torvals)가 처음 개발.
		- 1991년 8월 26일 리눅스 (Linux) 배포
	2) 발전과정
	
		- 커널(kernel) : 프로세스 관리, 파일 시스템관리, 메모리 관리 등 (**)
		- 최초 공개된 리눅스 커널:  버전 0.0.1
		- 리눅스 재단:  2007년 설립(  삼성전자, 메타, 애플, ... )
		- 현재 버전(2025년 기준): ubuntu 24.04.1 LTS / Debian 13
			* 리눅스 배포판( 커널 + 으용프로그램 ( 메모장, 웹브라우저 등 )) 
				http://namu.wiki/w/Linux/배포판
	
	3) GNU 프로젝트
		
		가.  개념
			- GNU is Not Unix ( GNU는 유닉스가 인다 ) - 그누라고 읽음.
			- 리처드 스톨만이 시작한 자유 소프트웨어 운동이이다.
			-  FSF(Free Software Foundation) 협회를 만들어서 자유 소프트웨어 보급 추진. 
			- GNU선언문과 GPL(General Public License)를 발표함.
		
		나. 목표
			- 누구나 자유롭게 프로그램을 사용/복사/수정/배포 가능함.
			- S/W 소스코드는 반드시 공개향됨 ( ***)
				ex. Linux, MySQL, Apache 등 ...

				ex.

							|
						VMWare host-only
							|

				|
				|	VMWare	---------------------------------
				|	|
				|	|		Linux -----			Linux----
				|	|		|						|
				|	|		|	eth(NIC)		|	eth(NIC: Network Interface Card)
				|	|		|----------			|----------
				|	|
				|	|		Vmnet8			Vmnet1
				|	|--------| |--------------| |---------------
				|	      172.16.8.0		  172.16.1.0

	카. pem( Privacy Enhanced Mail) 파일 이용.
	- password 입력없이 로그인 가능.
	- 비대칭키를 활용하는 방법.
	- 전체 아키택처
	
		서버(ubuntu) <------------------------------------------------------- 클라이언트( window )	
		
		a. 서버에서 공개키(public key)와 개인키(private key)를 생성
		b. 서버에 공개키(public key)를 저장
		   클라이언트에는 개인키(private key) 저장
		c. 클라이언트가 서버에 접속할 때 비밀번호 대신에 개인키를 이용해서 접속
		d. 서버에서는 클라이언트가 제공한 개인키와 공개키를 이용해 key pair 검증
		   맞으면 로그인, 틀리면 로그인 실패
	
	# ubuntu 작업
		
		1) 공개키와 개인키 생성.
		   ssh-keygen -q -N "" -f ubuntu_user1_key.pem
		   ==> ubuntu에 다음과 같은 2개의 파일이 생성됨.
			   ubuntu_user1_key.pem 		: 개인키, 클라이언트인 윈도우에 저장
			   ubuntu_user1_key.pem.pub		: 공캐키, 서버에 저장
			   
		2) 공개키를 지정된 파일에 덮어쓰기
		cat ubuntu_user1_key.pem.pub >> ~/.ssh/authorized_keys
		cat .ssh/authorized_keys
		ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIFbYGoLjwtIl81Cpr9PQYeojQ1uVcyv8Lo3uNHDvFFwk user1@ubuntu
		
		3) 공개키 파일의 권한 낮추기
		chmod 600 ~/.ssh/authorized_keys
		
		4) 클라이언트에 개인키 저장하기
		ubuntu_user1_key.pem 
		MobaXterm에서 파일 선택 > 좌클릭 > download 선택해서 윈도우에 다운로드	
		
	# window 작업
		MobaXterm > Session > SSH >
		Remote host: 172.16.8.10
		User name:	user1
		port: 22
		
		Addvanced SSH Setting > Use Private Key에서 다운받은 ubuntu_user1_key.pem 선택

1. 프롬프터와 홈디렉터리
	
	1) 프롬프터(prompt) 개념
		- 사용자의 명령을 기다리는 표시.
		- ubuntu의 프롬프트 기본은 다음과 같다.
		
		 user1@ubuntu: ~$
		 
		user1: 사용자 계정
		ubuntu: 호스트명 # cal /etc/hosetname 에서 확인 가능.
		~ : user1의 사용자의 홈디렉터리 경로
			/home/user1
			
		$: 일반 사용자에서 사용하는 쉘프롬프트
			일반 사용자가 할 수 있는 작업들
				- 프로그램 실행.
				- 파일생성
				- 자신만의 홈디렉터리( ex. /home/user1 )안에서만 작업이 가능(****)
				
		#: root(관리자)에서 사용하는 쉘프롬프트
			root 사용자가 할 수 있는 작업들
				- 시스템 전체 권한을 가져서 모든 작업들을 처리가능.
				- 사용자생성
				- 패키지 설치 ( apt install, apt remove 등 )
				- 서비스 시작/종료
			
		- 프롬프트에 많은 정보를 얻을 수 있음
		ex. 현재 사용자, 호스트명, 현재경로, 현재 쉘
	
	2) 쉘과련 정보 얻기
		- 현재사용자 조회: whoami
		- 호스트정보: hosetname
		- 현재 쉘정보: 환경변수에 쉘정보 저장. SHELL = 쉘	( 윈도우에서 %JAVA_HOME%, Linux에서는 $SHELL)
							echo $SHELL
							/bin/bash ( 배시 쉘: 기본 쉘이다)
		
		- 프롬프트 포맷: 환경변수에 쉘정보 저장. ps1 = 프롬프트포맷
								echo $PS1
								변경가능. ( exprot PS1 = "변경값" )

2. 일반사용자에서 관리자로 변경하는 방법
	
	1) 한번만 관리자로 변경해서 실행 ( 초보자에게 권장 )
		
		- sudo 명령어
		ex. sudo apt update
			 sudo apt install
			 
	2) root로 쉘 변경 ( $ -------> #)
	
		가. 현재 사용자 경로를 유지하고 관리자로 변경하는 방법.
		
			문법: sudo -s ( sudo su 와 유사 )	

			root@ubuntu: /home/user1# apt update <== sudo 없이 실행가능.
		
		나. root 계정으로 변경하는 방법
			
			문법: sudo su -

			ex.
				user1@ubuntu:~$ sudo su -
				root@ubuntu:~# pwd
				/root			
		
		
	3) root 계정 인증한 캐시 삭제.
	
		문법: sudo -k
	
	/////////////////////////////////
	# su 명령어
	
		기능: 사용자 변경
		문법: 
				su					: 관리자로 변경

				su - 사용자명	: 사용자가 바뀌며 사용자 환경( 사용자 계정의 홈디렉터리)으로 변경된다.

						 1  ipconfig

						 3  ping 8.8.8.8
						 ...
						 
					history가 저장된 물리적인 파일: ~/.bash_history
					history 완전 삭제 : rm -rf ~/.bash_history

	14) 파일 및 디렉터리 복사
		
		가. 문법: cp [옵션] 원본 대상(target)
		
		나. 특징
			원본 및 대상파일: 파일이거나 디렉터리가 될 수 있음
			원본: 여러개 지정가능
			ex.
				cp 원본파일 타겟파일
				cp 원본파일1 원본파일2 ... 타겟 디렉터리
				cp 디렉터리 원본파일1 원본파일2 ... 타겟 디렉터리
				
				
		다. 옵션
			- i : interactive 기능, 덮어쓰기 유무를 묻는다
			- p : 원본파일이 속성(mode, 소유자, 시간)까지 유지되어 복사됨.
			- r : recursive, 원본에 디렉터리가 있는 경우 같이 복사
			
			
		실습1: 
			$ cp /etc/passwd ./users.txt
			$ cp /etc/passwd ./log1/users.txt	# 타겟에 복사될 디렉터리 포함가능.
		
			$ cp -i /etc/passwd users.txt			# 덮어쓰기 전에 물어봄
			cp: overwrite 'users.txt'? yes
			
			cp hello.txt users.txt first/  		# 있으면 복사되고 없으면 오류출력됨
			
			cp log2 users.txt first/				
			cp: -r not specified; omitting directory 'log2'		# -r 옵션을 붙이라는 경고문이 가이드가 뜬다
			
		실습2: -p		
			
			- users.txt의 소유자 확인:			
				ls -l | grep users.txt
				-rw-r--r-- 1 user1 user1 2907 May 28 10:04 users.txt
				==> 소유자: user1
				
			- 관리자 권한으로 복사:				
				sudo cp users.txt adminCopy.txt
				ls -l | grep adminCopy.txt
				-rw-r--r-- 1 root  root  2907 May 28 10:12 adminCopy.txt	# 
				==> 소유자: root
				
			- p옵션으로 복사:				
				sudo cp -p users.txt adminCopy2.txt
				ls -l | grep adminCopy2.txt
				-rw-r--r-- 1 user1 user1 2907 May 28 10:04 adminCopy2.txt
				==> 소유자, 생성시간이 원본과 동일

	19) 하드링크 (hard link)
		가. 개념: 같은 inode 값을 갖는 다른 파일 
			////////////////////////////////
				inode란
				- 리눅스가 관리하는 자원(파일, 디렉터리, 장치,...)의 실제 저장되는 주소값 의미
			////////////////////////////////
			
		나. 문법: ln 원본 대상(타겟)
		
		다. 특징:
			- 디렉터리 지정 불가 ( 디렉터리는 동일한 주소값을 가질 수 없기 때문)
			- inode가 같으면 데이터도 동일
			- 한쪽이 수정되면 다른쪽도 영향을 받는다( like 자바 깊은복사 )
			- 한쪽이 삭제 되어도 다른쪽에는 영향이 없다
			  ( 삭제: inode 참조하는 링크를 삭제하는 것 )
			- inode를 삭제하면 링크된 파일 전체가 삭제된다.
		
		라. 목적
			- 백업용도: 하나를 삭제해도 나머지는 유지
			- 보안이슈: 중요한 파일명을 노출하지 않을 수 있음
			
		실습:
			echo "hello" >> main.txt		# 원본파일
			ln main.txt main_copy.txt		# 하드링크 파일
			$ ls -il | grep main
			787438 -rw-rw-r-- 2 user1 user1    6 May 28 14:24 main_copy.txt
			787438 -rw-rw-r-- 2 user1 user1    6 May 28 14:24 main.txt
			==> inode가 동일하다, inode 링크 갯수: 2
			
			$ cat main.txt main_copy.txt	# 내용이 같은지 확인
			$ echo "world" >> main.txt		# 원본 파일 수정
			$ cat main_copy.txt
			hello
			world
			
			$ rm main.txt						# 원본 삭제
			$ ls -il | grep main
			787438 -rw-rw-r-- 1 user1 user1   12 May 28 14:27 main_copy.txt
			==> inode는 유지되며, inode 링크 갯수가 줄어든다.
			
	20) 소프트링크 (soft link)
		가. 개념: 바로가기 기능 ( 윈도우에서 바로가기 기능: 원본이 삭제되면 바로라기 아이콘이 깨짐)
		
		나. 문법
			ln -s 원본 대상(타겟)
			
		다. 특징
			- 디렉터리 가능
			- inode가 다름
			- 원본 수정하면 영향을 받는다.
			- 원본을 삭제하면 대상의 링크가 깨진다. ( ls 입력시 빨간색으로 출력됨, 해결: rm 소프트링크 )
		
		라. 목적: 경로단축
		
		# 실습
			$ echo "hello" > m2.txt
			$ ln -s m2.txt m2_soft.txt
			$ ls -il | grep m2		# inode가 서로 다름 
			787440 lrwxrwxrwx 1 user1 user1    6 May 28 14:45 m2_soft.txt -> m2.txt		
			787439 -rw-rw-r-- 1 user1 user1    6 May 28 14:44 m2.txt
			==> inode 다름, 링크 갯수는 각 1개, ` -> ` 표시는 softlink를 의미한다
			
			$ echo "m2.txt update" >> m2.txt		# 원본수정
			$ cat m2_soft.txt							# 소프트링크 파일도 원본의 영향을 받는다
			hello
			m2.txt update
			
			$ rm m2.txt	# 원본삭제
			$  ls -il
			787440 lrwxrwxrwx 1 user1 user1    6 May 28 14:45 m2_soft.txt -> m2.txt
																			  ---------------------
																				터미널에서 이부분이 빨간색
																				==> 링크가 깨진 상태이다.
			
			$ rm m2_soft.txt 		# 원본과 링크가 깨졌으므 삭제해야 한다.
			
		# 실습: 디렉토리에 소프트링크 지정
			$ mkdir temp
			$ touch temp/test.txt
			$ ln -s temp temp_soft
			
			$ ls temp_soft
			test.txt
			
			$ ls -il | grep temp
			787439 drwxrwxr-x 2 user1 user1 4096 May 28 15:07 temp
			787442 lrwxrwxrwx 1 user1 user1    4 May 28 15:07 temp_soft -> temp

2. 리다이렉션( redirection )

	- 동작: 명령어의 입출력의 방향을 바꾸는 방법.
			  일반적으로 콘솔의 출력되는 방향을 파일로 출력되도록 방향을 바꿈
			  파일이 없으면 자동으로 파일을 만들어준다
			  
	- 문법:	명령어 > 	(>, >>, 2>, <)
	
	#	표준입력 : < 
	
		표준출력(정상출력)
				 > : 덮어쓰기
				 >>: 추가	( appaned )
				 
		표준에러 : 2> 		( 비정상, 오류출력)			
	
	#	표준 입력/표준 출력/표준 에러
	
	$ file /dev/stdin		# 0번 자바의 System.in 동일
	$ file /dev/stdout	# 1번 자바의 System.out.println 동일
	$ file /dev/stderr	# 2번 자바의 System.err.println 동일

	#ex.
		ls > file.txt								# 덮어쓰기
		ifconfig >> ifconfig.txt				# 추가(append)
		ifconfig | grep ether > MAC.txt 		
		wc -l < file.txt							# 입력 리다이렉션
		ls text.txt wrong.txt 2> error.txt	# ls 실행했을 때 출력되는 오류를 저장.
		ls text.txt wrong.txt > success.txt 2> error.txt	# ls 실행했을때 출력되는 정상출려과
																			  오류 출력을 분리해서 저장.
  
	# 실습 
		ls > file.txt 		# 덮어쓰기. 파일 없으면 생성
		ls >> file.txt 	# 추가(append)
		
		ifconfig | grep ether > MAC.txt		
		wc -l < file.txt	# file.txt 읽어서 라인수 출력
		
		# 정상출려과 에러출력 분리하기			
			# 1. 정상출력만 있는 경우
				ls file.txt > out.txt
			
			# 2. 비정상출력				
				ls wrong.txt > errort.txt		# 오류가 발생, 표준출력(정상출력) > 으로 리다이렉션 불가
				ls: cannot access 'wrong.txt': No such file or directory

				ls wrong.txt 2> error.txt		# 오류용 2> 사용했기 때문에 정상적으로 리다이렉션
			
		# 정상출력과 비정상출력 모두 있는 경우
			==> 동작박식은 정상출력값은 out2.txt에 정사적으로 리다이렉션이 되고
				 오류출력값은 그냥 콘솔에 출력됨.
				 
				ls file.txt wrong.txt > out2.txt
				ls: cannot access 'wrong.txt': No succh file or directory
			
			==> 동작장식은 오류출력값은 error2.txt에 정상적으로 리다이렉션이 되고 
				 정상출력값은 그냥 콘솔에 출력됨.
				 
				ls file.text wrong.txt 2> error2.txt
				file.txt
				
			==> 동작장식은 오류출력값은 error3.txt에 정상적으로 리다이렉션이 되고 
				 정상출력값은 out3.txt에 정상적으로 리다이렉션이 된다
				 
				 ls file.txt wrong.txt 2> error3.txt > out3.txt

		: 일반 사용자와 분리해서 관리하가 위해서 /home 디렉터리가 아닌 /root가 홈디렉터로 관리됨
		: 관리자만 할 수 있는 역할
			- 사용자생성/삭제
			- 패키지설치/삭제
			...
		
2. 사용자 정보 관리 파일

	- 사용자 정보 파일
		: /etc/passwd
		
		ex. 
		 root:x:0:0:root:/root:/bin/bash
		 user1:x:1000:1000:user1:/home/user1:/bin/bash

		구성요소
		user1		: 계정명
		x			: 암호화된 비번, x ==> 외부파일(/etc/shadow)에 저장되어 있다.
		1000		: 계정 ID ( UiD, UserID )
		1000		: 그룹 ID ( GID, GroupID)
		user1		: 커맨트  ( 임의의 값 )
		/home/user1	: 홈디렉터
		/bin/bash	: shell
		
	- 사용자 비번 파일
		: /etc/shadow
		
		구성요소
		user1:$6$l20e37U9exJg9tGz$iwUk4JKOqBOgps9pQQzxhhgZfiHoVySiAwHC74QzTIhqh0/vN.wM5DlEm6jaHU0s 
		
		
3. 사용자 그룹
	- 개념: 여러 사용자들을 묶어서 관리하기 위해
	- 그룹정보:
		/etc/group
		
		ex.
			cat /etc/group
			user1:x:1000:
			
			user1	: 그룹명
			x		: 암호화된 비번
			1000	: GID( GroupID )
			
	- 그룹종류
		a. Primary Group: 사용자 기본그룹

			- 명령어: id 사용자	( ex. id user1 )

			$ id user1							 
			uid=1000(user1) gid=1000(user1) 		# 기본그룹
			groups=1000(user1),4(adm),24(cdrom),27(sudo),30(dip),46(plugdev),100(users),114(lpadmin)	# 추가그룹
		
		b. Secondary Group: 사용자의 추가그룹
		
			- 명령어: groups 시용자명

			$ groups user1
			user1 : user1 adm cdrom sudo dip plugdev users lpadmin
			
4. 사용자 생성 / pw 설정
	
	a. 문법: 
		sudo useradd [옵션] 사용자명 	# 사용자 생성
		sudo passwd 사용자명 			# pw 설정
		
		sudo userdel -r 사용자명		# 사용자 삭제 
		
	b. 옵션
		- m : 홈디렉터리 생성, 지정하지 않으면 홈디렉터리 생성되지 않음
			  기본적으고 /home/사용자명 으로 생성됨.
			  
		- d : 명시적으로 홈디렉터리 설정
		- s : 사용하고자 하는 쉘 지정. ( 기본은 /bin/sh )
		- G : 추가 그룹 지정
		- g : 기본 그룹 지정
		
	ex.
		sudo useradd -m user2			# 홈 디렉터리 생성.	/home/user2
		sudo passwd user2
		$ sudo tail -n 5 /etc/shadow	# pw 확인
						
		sudo useradd -m -d /home/project/user3 user3	 # 홈 디렉터리 생성 (/home/project/user3)
		
		# 먼저 dev 그룹 생성
		sudo group
		sudo useradd -m -g dev user4  # 홈디렉터리 생선. Primary Group을 dev로 지정
		
		sudo useradd -m -G sudo,users user5	# 홈디렉터리 생성. Secondary Group을 sudo, users 지정
		$ id user5
		uid=1004(user5) gid=1004(user5) groups=1004(user5),27(sudo),100(users)

		sudo useradd -m -s /bin/bash user6	# 홈디렉터리 생성. shell 지정
		user6:x:1005:1005::/home/user6:/bin/bash

		# 사용자 변경
		su 사용자명
		exit로 돌아감
		
		# 사용자 삭제 
		- sudo userdel -r 사용자명

7장. 파일 접근 권한
/////////////////////////////////////////////////		
	
1. 개념
	- 파일(디렉터리 포함)에 무단으로접근하는 것을 방지하기 위한 방법.
	- 3가지 권한으로 관리 가능( 읽기/쓰기/실행. rwx )
	
2. 3가지 권한	
	- 읽기권한	: r(read) 	
	- 쓰기권한	: w(write) 
	- 읽기권한	: x(execute)
	- 권한없음  : -

	ex. 
		$ ls -al
		rw-rw-r--
		-------------------
		rw-	: 소유자권한
		rw-	: 그룹권한
		r--	: Other 권한
		-------------------

3. 파일접근권한 변경1 _ 기호모드
	-------------------------------------------------
	구분						| 문자/기호 |				
	-------------------------------------------------
	사용자 카테고리 문자	| u			| 파일소유자 의미
	(권한을 부여/취소할	| g			| 소유자가 속한 그룹
	대상을 정할때 사용)	| o			| 기타사용자
								| a			| 모든사용자
	--------------------------------------------------
	연산기호					| +			| 권한부여
	( 권한을 부여/취소)	| -			| 권한제거
								| =			| 접근 권한 설정
	--------------------------------------------------
	접근권한문자			| r			| 읽기권한
								| w			| 쓰기권한
								| x			| 실행권한
	--------------------------------------------------
	
	가. 문법: chmod 권한지정 파일
	
	ex. chmod
		u+x	: 파일소유자에게 쓰기 권한 부여.
		u+rwx	: 파일소유자에게 읽기, 쓰기, 실행 권한 부여
		
		g-w	: 소유자그룹에서 쓰기 권한 삭제
		o+r	: 기타사용자에게 읽기권한 부여
		u+x, o+rwx	:	소유자에게 실행 권한, 기타 사용자에게 모든권한 부여
		a+x	: 모든 사용자에게 실행권한 부여
		u=rwx, o-w	: 소유자에게 모든권한 부여, 기타사용자 쓰기 권한 삭제
		ug=rwx: 소유자, 소유자 그룹에 모든 권한 부여
		o=		:	기타 사용자에게 아무 권한도 부여하지 않음

	#	실습
		touch exam.txx				# 실습 파일 생성
	
		chmod 000 exam.txt		# 권한 초기화
		chmod u+w exam.txt		# 소유자 쓰기 권한부여
		chmod u+rwx exam.txt		# 소유자 모든권한부여
		chmod o+r exam.txt		# 기타사용자 읽기권한 부여
		chmod ug=rwx exam.txt	# 소유자, 소유자그룹 모든권한 부여
		chmod g=,o=rw exam.txt	# 소유자그룹 모든권한 삭제, 기타사용자 읽기,쓰기권한 부여
	
3. 파일접근권한 변경1 _ 숫자이용(****)
	- 개념: 권한이 있으면 1, 없으면 0으로 표기 후 10진수로 표기.
	ex.
		chmod 745 text.txt 		
		---------------
		rwx : 111 --> 7
		r-- : 100 --> 4
		r-x : 101 --> 5
		==> rwxr--r-x
		
		chmod 641 text.txt => rw-r----x
		chmod 600 text.txt => rw-------

1. 프로세스 관리

	1) 개념: 실행중인 프로그램을 의미

	2) 특징: 
		- 부모/자식 관계로 구성됨 (계층적으로 구성됨)
		- 부모가 자식 프로세스를 생성하고, 자식프로세스가 실행된다
		  자식프로세스가 종료되면 부모프로세스에게 결과를 돌려줌
		- 모든 프로세스는 식별자를 가짐. (PID: 프로세스 아이디)
		- PID가 작을수록 중요한 프로세스이다.
		- 포그라운드(foreground) 및 백그라운드(background) 실행가능
		
	3) 프로세스 정보보기 			
		문법: 
			ps			# 현재 터미널에서 실행한 프로세스 정보만 출력.
			ps -ef	# 모든 프로세스 정보 출력
			___________________________________________________________
			UID          PID    PPID  C STIME TTY          TIME CMD
			user1     291512  148440  0 15:43 pts/0    00:00:00 ps -ef
			___________________________________________________________
			# 구성요소
			user1		: UID		(프로세스를 실행한 사용자)
			291512	: PID		(프로세스 아이디)
			148440	: PPID	(부모프로세스 아이디)
			0			: CPU 사용률
			15:43		: 시작시작
			pts/0		: 터미널
			00:00:00	: 사용시간
			ps -ef	: 실행 명령어
			
		#	ps -ef | grep 검색어 	# 현재 프로세스 중에 검색어만 출력ㅁ

	4) 주요 명령어
		
		- top		: 현재 실행중인 프로세스에 대한 정보를 주기적으로 출력	
		- fg 		: 백그라운드 작업을 다시 foreground 로 실행	
		- bg 		: 멈춰놓은 작업을 다시 background 로 실행	
		- &			: 백그라운드로 실행
		- ctrl + z		: 프로세스 중지	
		- ctrl + c		: 프로세스 종료	
		- kill pid		: 프로세스에 종료신호 보냄	
		- kill 9 pid	: 강제 종료
		
		
		# 실습1
			top		# 현재 실행 중인 프로세스
			ps -ef | wc -l		# 실행중인 프로세스 갯수
		
		# 실습2: foreground로 실행( 일반적으로 실행 )
			
			sleep 10		# 끝날떄 까지 기다리거나 ctrl + c 로 프로레스를 종료할 수 있다

		# 실습3: background 실행
		
			sleep 50 &		# background 실행
			
			jobs				# background 프로세스, 중지된 프로레세스 확인
			[1]+  Stopped                 top
			[2]-  Running                 sleep 50 &
			
			ps -ef | grep sleep
			user1       4597    3625  0 09:41 pts/0    00:00:00 sleep 100
			user1       4603    3625  0 09:42 pts/0    00:00:00 grep --color=auto sleep
			
			kill -9 4597	# PID 프로세서를 강제종료
			
		# 실습4: foreground --> background --> foreground
			sleep 100 		# foreground
			ctrl + z			# 프로세스 중지
			jobs				# 백그라운드 프로세스 확인
			
			bg	%1				# [1]에 해당하는 프로세스를 백그라운드로 실행
			jobs
			
			fg %1				#
			ctrl + c 		# 프로세스 종료

4. Special Variable

	1) 개념: 쉘 내부에 미리 정의된 변수 의미. ( 내장 변수 )
		- $0 : 파일명
		- $1,$2... : 10부터는 중괄호 지정한다 . ex . ${10},${11}
		- $# : 스크립트에 전달된 인자의 갯수
		- $@ : 전달된 모든 인자 전체 ( 개별 항목으로 유지 )
		- $* : 전달된 모든 인자 전체 ( 모든 인자를 하나의 문자열로 합침 )
		- $$ : 현재 실행중인 쉘 또는 스크립트의 PID
		- $? : 바로 직전에 실행한 명령어의 결과코드 ( 성공 , 이외값 실패 )
		- $! : 가장 최근에 백그라운드로 실행한 프로세스 PID
		
	
	# 실습 
		# test3.sh 작성
		------------
		#!/bin/bash

		echo "file: $0"

		echo "arg1: $1"
		echo "arg2: $2"
		echo "$#: $#"		# 인자 갯수
		echo "$@: $@"		# 인자 모두 전달
		echo "$*: $*"		# 인자 모두 전달
		echo "$$: $$" 		# 현재 실행중인 스크립트 PID
		-------------
		
		chmod 700 test3.sh
		./test3.sh one two		
		file: ./test3.sh
		arg1: one
		arg2: two
		2: 2
		one two: one two
		one two: one two
		2164: 2164
		
	# 실습 . $? 
		$ ls
		test2.sh  test3.sh  test.sh		# 명령 성공
		$ echo $?
		0				# 이전에 실행한 명령이 성공했음
		
		$ ls /temp	# 존재하지 않는 디렉터리 ==> 명령실패
		ls: cannot access '/temp': No such file or directory
		$ echo $?
		2				# 이전 명령이 실패했음 알린다.

5. 연산자

	1) 숫자 비교 연산자( 수치 데이터만 가능하다 )
		
		- 조건식 문법: [[ 조건식 ]]		# 공백이 필수 이다, [ 조건식 ]은 과거문법

		- eq :	같다
		- ne :	같지 않다
		- gt :	크다
		- lt :	작다
		- ge :	크거나 같다
		- le :	작거나 같다
		
		ex. 
			$ num=10
			$ [[ $num eq 10 ]]		# 성공 / 실패
			$ echo "result: $?"
			result: 0

	2) 문자열 비교 연산자
	
		- =, ==	:	문자열이 같다
		- 	!=		:	문자열이 같지 않다
		- 	-z		:  문자열 길이가 0 이다
		-	-n		:	문자열길이가 0 이 아니다
		
		ex.
			name=hello		# "hello" 동일
			[[ $name == "hello" ]]		# 같은가
			echo "result: $?"
			
			[[ $name != "hello"]]		# 같지 않은가
			echo "result: $?"
			
			[[ -z $name ]]		# 길이가 0인가
			echo "result: $?"
			
			[[ -n $name ]]		# 길이가 0이 아닌가
			echo "result: $?"
			
		# 패턴 매칭 가능
			[[ $name == h* ]]		# h로 시작하는가
			[[ $name == *o ]]		# o으로 끝나는가
			
	3) 논리 연산자
		
		- &&	: 그리고( and )
		- ||	: 또는( or )
		- !	: 부정( not )
		
		ex.
			n=8
			[[ $n -eq 10 || $n -lt 10 ]]
			[[ $n -eq 10 && $n -lt 10 ]]
			[[ !($n -eq 10) ]]
	
	4) 산술연산자
	
		: +, -, *, /, %  지원한다
		
		문법:		$(( 연산 ))		# 소괄호 두번이다
		
		ex. 
			a=10
			b=3
			echo $((a + b))
			echo $((a - b))
			echo $((a * b))
			echo $((a / b))
			echo $((a % b))
	
	5) 증감 연산자
		: ++ , -- / 전치, 후치 지원한다
		계산 시	:	$(( 연산 ))
		
		ex.
			$ n=10
			$ n2=$(( ++n ))
			$ echo "$n,  $n2"
			11, 11

			$ x=10
			$ x2=$(( x++ ))
			$ echo "$x,  $x2"
			11, 10
			
	6) 파일 검사 연산자
	
		- e	: 파일디렉터리가 존재여부
		- f	:  일반파일 ( 텍스트 , 로그 등 )
		- d	: 디렉터리 여부
		- r	: 읽기가능 여부
		- w	: 쓰기 가능 여부
		- s	: 크기가 0 보다 크다
		- L	: 심볼릭 링크 여부
	
		ex. 
			[[ -e test.sh ]]		# test.sh 파일이 있는가
			echo $?
			
			[[ -d tmp/ ]]			# tmp가 디렉토리인가
			echo $?
			
			[[ -s test.sh ]]			# 크기가 0보다 큰가
			echo $?
			
			ln -s test.sh test_copy.sh
			[[ -L test_copy.sh ]]	# tmp가 디렉토리인가
			echo $?

10. 배열
