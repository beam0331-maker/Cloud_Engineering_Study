1. 서버운영의 역사 
	
	1) 물리서버시대(Bare Metal)		
		- 운영체제에 하나의 서버만 설치 ( 하나의 서비스만 지원 )
		- 서버자원이 남아도 활용불가
		- 문제점 : 서버비용 증가
					  확장성이 떨어짐
					  장애발생시 복구 어려움
	
	2) 가상서버시대(Virtual Machine)		
		- 하나의 운영체제(host OS)에 여러 개의 가상 OS(guset OS)	설치됨.
		- 서버자원 활용가능 및 서비스 분리가능
		- 문제점 : 개별적으로 OS 포함 ( OS가 공유안됨 *** )
					  무겁다, 부팅이 느리다
					  디스크 / 메모리 사용량이 크다

		- VM = OS + 라이브러리 ( ex. JDK, JRE ) + 앱(ex.SpringBoot)
		- 여러개의 가상 OS를 설치할 수 있으나 서로 공유가 안됨.
		
	3) 컨테이너 시대(Docker)			
	: 하나의 OS위에 다양한 OS를 돌린다. VM을 거치지 않기 때문에 host의 자원을 공유할 수 있다.
		- 핵심: OS가 공유 가능. 앱만 분리
		- 가볍고 빠름.
		- 동일한 환경으로 실행보장 (****)
		( Any OS, Any Language, Any App, Any Where)

2. Container 관련 내용

	1) OCI ( Open Container Initiative )

	3) CRI-O

		- K8s(Kubernetes)에서 사용하는 실행환경이다

3. Docker
	1) 개념
		- 컨테이너를 만들고 관리하기 위한 오픈소스 S/W
		- 한번 만들면 어떤ㄷ 환경에서든 동일한 환경 구축 가능.
		
	2) 장점
		- 환경 불일치 해결 ( 어디서 실행해도 동일한 결과 보장 )
		- 배포 표준화 및 자동화
		- 빠른 배포 및 롤백 
		- 마이크로서비스 어플리케이션(MSA) 개발에 최적화
			-> 기존의 서비스를 한번의 배포하는 아닌, 시스템의 기능을 개별로 분리하여 배포하는 방식
				ex. 게시판의 회원가입, 게시글, 작성,... 기능을 개별로 어플리케이션으로 만들어 배포
				
	3) Docker 기본 흐름
		
		////////////////////////////////////
			registry ----------------> image ----------------> container
		ex. vsc 홈페이지				   vsc 프로그램			  vsc 실행 ( vsc 프로세스 )
			 intellij홈페이지				intellij IDE			  intellij 실행 ( intellij 프로세스 )
		////////////////////////////////////
		
		가. 개념
			Registry ( image 저장소  )
				|			ex.  Docker hub: 공식적인 저장소( https://hub.docker.com/ ) 
				|				  AWS ECR
			image		( OS + 실행환경 + 라이브러리 + app 관련 정보들이 저장됨)
				|			틀역할 담당.
				|		만드는 방법 2가지: Dockerfile, docker-compose.yml(yaml)
				|		
			container ( image를 실제 실행 했을때)
			
		나. Registry
			- image 저장소
				ex. Docker hub(공식적인 저장소), AWS ECR
			
			- 역할 : 이미지 다운로드.	ex. docker pull 이미지명:tag
						이지미 업로드.		ex. docker push 이미지명:tag 
		
		다. image
			- 컨테이너를 만들기 위한 틀 역할 담당
			- 구성요소: 
				OS	(base 이미지 ex. ubuntu ...)
				실행환경
				라이브러리
				설정파일
				app	
				==> 위 구성요소들이 포함 될 수 있다. ( 필수는 아니다 )	
				
			- 특징
				: Read-Only(***)		==>	수정 불가능, 필요 시 이미지를 다시 만들어야 한다.
				: 실행되지 않sms 정적파일(static)
				: 레이어 아키텍쳐(Layer Architecture)로 구성됨. 즉 여러 layer로 구성됨.(*****)
					==> 변경 시, 필요한 layer만 교체되고 나머지 layer 재사용( 캐시 )
				
			- 종류:
				a. 빌드된 이미지 (pre-buil image) : docker hub 제공
				b. 커스텀 이미지 : 개발자가 직접 만든 이미지
				
		라. container
		
			- 정적인 이미지를 실행한 프로세스
			- 특징
				: Read-Write(****)
				: 하나의 이미지에서 여러개 생성 가능
				: private 구조 ( 격리된 환경 ). 따라서 직접 접근이 불가 (***)
				: 휘발성 ( 컨테이너에서 수정된 변경사항이 일시적임) (***)
					==> 영속성을 가지기 위해서 볼륨( Volume, host에 임의 파일이용 )사용	# host에 수정 내용을 저장한다

5. hello-world 이미지 실행
			
	1) docker run hello-world 실행
	
		- 내부 동작순서
			가. 로컬에서 hello-world  이미지를 찾음
				 (있다면 실행(container 생성),
				 없아면 docker hub에서 다운로드 된다)
				 
			나. 없으므로 docker hub에서 다운로드된다.
			다. 다운로드 된 이미지 이용해서 컨테이너 생성.
			라. 실행하고 이미지 출력 후 종료.
		
		- 로컬 이미지 정보 확인
			
			docker images
			
			IMAGE                ID             DISK USAGE   CONTENT SIZE   EXTRA
			hello-world:latest   0e760fdfbc48       25.9kB         9.49kB    U 
			
			- IMAGE 		: hello-world
			- tag			: latest, 지정하지 않으면 자동으로 latest가 붙음. 
							  latest라고 해서 가장 최신버전이라고 생각하면 안된다.
								==> 명시적으로 버전 지정을 권한한다 ( ex. :latest:v3)
			- ID			: 로컬에 있는 이밎 id값, 식별자용이다	( ex. Digest: sha256:0e760fdfbc48)

			- DISK USAGE	: 실제 이미 크기
			- CONTENT SIZE	: 이미지를 관리하기위한 디스크 크기
			- EXTRA			: 이미지 사용여부
			
		- 컨테이너 정보 확인
		
			docker ps	 : 실행중인 컨테이너 정보 출력
			docker ps -a : 실행중 + 종료된 컨테이너 정보를 출력
			
			CONTAINER ID   IMAGE         COMMAND    CREATED         STATUS                     PORTS     NAMES
			9297a2364a87   hello-world   "/hello"   7 minutes ago   Exited (0) 7 minutes ago             practical_engelb
			
			- CONTAINER ID	: 실행중 container를 구분하기 위한 식별자
			- IMAGE			: 컨테이너를 만든 템플릿 IMAGE
			- COMMAND		: 명령어
			- CREATED		: container 생성시점.
			- STATUS			: container 상태를 알려준다. ( ex. Created, Running, Exited, Stop, ... )
			- PORTS			: 외부에서 접근을 위해 할당한 포트번호.
			- NAMES			: container 이름. 명시적으로 지정하지 않으면 랜덤하게 작성된다 ( container 식별자 )
			
			# 식별자			: container를 핸들링 하는데 사용. ( ex. CONTAINER ID, NAMES )

6. nginx 웹서버 실행
	1) docker run nginx 실행 ( foreground로 실행 )
	
		- 내부 동작순서
		
			가. 로컬에서 nginx 이미지를 찾음
				 (있다면 실행(container 생성),
				 없아면 docker hub에서 다운로드 된다)
				 
			나. 없으므로 docker hub에서 다운로드된다.
				 ==> 명시적으로 tag를 지정하지 않으면 자동으로 latest가 다운로드됨.
				 
			다. 다운로드 된 이미지 이용해서 컨테이너 생성.
			라. 실행하고 이미지 출력 후 종료.
			
	2) docker run -d nginx:1.30-alpine 실행 ( background 실행 )
	
		- 내부 동작순서
		
			가. 로컬에서 nginx:1.30-alpine 이미지를 찾음
				 (있다면 실행(container 생성),
				 없아면 docker hub에서 다운로드 된다)
				 
			나. 없으므로 docker hub에서 다운로드된다.
				 ==> 명시적으로 tag를 지정. nginx:1.30-alpine가 다운로드됨.
				 
			다. 다운로드 된 이미지 이용해서 컨테이너 생성.
			라. 실행하고 이미지 출력 후 종료.	
			
			
	2) docker run -d -p 1234:80 nginx		
	
	  # 포트 포워딩(port forwarding): 
       개념: 컨테이너는 private 환경이기 때문에 외부에서 직접 접근이 불가함.
				 따라서 외부에서 접속할 수 있는 port를 open해야 됨.
				 이것이 포트 포워딩(포트매핑) 임.
	   문법:
	        -p host에서요청포트:docker내부포트  ex. -p 1234:80,  -p3306:3306

1. image 명령어
	- 특징: 읽기 전용(read-only)
			  레이어 아키텍쳐
			  
	1) 이미지 보기
	
		- 개념 : 로컬에 저장된 Docker 이미지 목록 조회.
		- 문법 : docker image ls [OPTIONS] [REPOSITORY[:TAG]]
					
					docker image list
					docker images	( 가장 많이 쓰임 )
					
		- 옵션
			-a, --all : 모든 이미지 포함해서 조회 ( untaged, dangling 이미지는 기본적론 숨겨져있다 )
							# untaged 이미지 
							  : 하나의 이미지를 docker tag 명령어로 리눅스의 하드링크처럼 여러버전을 만들 수 있음. 이 경우에 특정 버전을 삭제하면 진짜 이미지가 삭제되는 것이 아니고 untageed 상태로 남게 된다.
							  
							# dangling 이미지
							  : 동일한 이미지(이미지:tag 가 같은경우)를 다시 빌드 할때, 기존 이미지가 tag를 잃게 되 상태의 이미지를 의미한다. <none>:<none> 포맷을 가진다.
			
			-q, --quiet : 이미지 ID만 출력
			--no-trunc	: 정보를 절삭하지 말고 전체출력
			--digests	: Docker hub에 있는 이미지 식별자
			-f, --filter: 조건으로 필터링 가능
							  https://docs.docker.com/reference/cli/docker/image/ls/#filter 
							  ex. docker images -f "before=nginx:latest"		
								   docker images -f "since=nginx:latest"
			--format		: 출력 형식 지정
							  https://docs.docker.com/reference/cli/docker/image/ls/#format  참조할것
							  기본은 table
							  
							///////////////////////////////////////////////////////////////////////////
								다음과 같은 속성 사용 가능.
								Placeholder			Description
								-----------------------------
								.ID					Image ID
								.Repository			Image repository
								.Tag					Image tag
								.Digest				Image digest
								.CreatedSince		Elapsed time since the image was created
								.CreatedAt			Time when the image was created
								.Size	Image			disk size
							///////////////////////////////////////////////////////////////////////////
								ex. docker images --format "table {{.ID}}\t{{.Repository}}\t{{.Tag}}"
				
		# 실습
		
			docker image ls
			docker image ls -a
			docker images

	2) 이미지 세부 정보( metadata) 조회
	
		- 개념 : 로컬에 저장된 Docker 이미지의 세부 정보(metadata) 조회.

				docker inspect nginx -f "{{.Config.ExposedPorts}}"

			==> -it	:  컨테이너에 접속시 사용하는 옵션

			5단계: 종료

2. Docker에서 데이터를 영속성으로 관리하는 방법 2가지.
	
	- 2가지 방법 모두 데이터를 영구적으로 보존이 가능함.
	- 차이점은 관리주체와 사용목적이 다르다
	
	1) 볼륨(Volume) 이용
		- 관리주체: Docker가 관리
		- 생성방법: docker volume create 볼륨명
						ex. docker volume create my-volume

		- 실제사용경로: -v my-volume:/user/lib
							# docker가 관리하므로 사용경로를 명시적으로 지정할 필요없다 
		
		- 이식성(다른곳에서 사용): Docker가 관리하기 때문에 이식성이 우수
		- 성능: Docker가 관리하기 때문에 안정적
		- 목적: DB 데이터 (***)  ex. mysql
	
	2) 바인드마운트(Bind Mount)이용
		- 관리주체: 사용자(개발자)가 직접관리.
						직접 host가 폴더 생성하고 경로 관리해야된다.

4. 주요 명령어 정리 

	1) FROM
		- 문법: 
			FROM [--platform=<platform>] <image>				 [AS <name>]
			FROM [--platform=<platform>] <image>[:<tag>]		 [AS <name>]
			FROM [--platform=<platform>] <image>[@<digest>]	 [AS <name>]
			# AS <name> :  별칭. 멀티-스테이징-빌드 패턴시 참조해서 사용한다.
			# https://docs.docker.com/build/building/best-practices/
			# https://docs.docker.com/build/building/multi-stage/
			
		- 용도: base image 지정
		- 특징 : 필수, 가장 우선 만들어진다.
					여러번 사용 가능.
	2) WORKDIR
		
		- 문법 : WORKDIR /path/to/workdir
		
		- 용도 : 내부 작업 디렉터리 지정( 지정된 디렉터리가 없으면 자동생성)
					이후에 사용하는 RUN, CMD, ENTRYPOINT 등의 기준으로 사용됨.
					
		
	3) COPY
	
		- 문법 : COPY [OPTIONS] <src> ... <dest>
					COPY [OPTIONS] ["<src>", ... "<dest>"]
					 
					COPY [--from=<image|stage|context>] <src> ... <dest>  # multi-stage  패턴에서 사용됨
					
		- 용도 : 호스트 파일을 컨테이너 이미지에 복사
		
	4) RUN
	
		- 문법 : # Shell form
					RUN [OPTIONS] <command> ...
					
					# Exec form
					RUN [OPTIONS] [ "<command>", ... ]
					
		- 용도 : 이미지가 만들어지는 동안 ( docker build ) 실행됨. 
					한번만 실행되고 실행된 결과가 이미지 Layer에 저장된다. 
					
			ex. RUN apt update && apt full-upgrade -y				 
				 RUN npm install
				 
	5) CMD
		
		- 문법 : CMD ["executable","param1","param2"] (exec form)
					CMD ["param1","param2"] (exec form, as default parameters to ENTRYPOINT)
					
					CMD command param1 param2 (shell form)
					
			 ex : CMD ["node", "app.js"]
					CMD ["java", "-jar","app.jar"]
					
		- 용도 : 컨테이너가 실행될 때 실행된다(*******)
					docker run 할 때 CMD 명령어를 덮어쓰기 가능함
					
					ex. docker run -d --name my-app -p 8080:40 app2.js		# app.js가 app2.js로 동적으로 변경된다.
					
	6) ENTRYPOINT ( 고정 명령어 )
		
		- 문법 : ENTRYPOINT ["executable", "param1", "param2"] (exec form)
				
					ENTRYPOINT command param1 param2 (shell form)
		
		- 용도 : 컨테이너가 실행될 때 실행된다
					docker run할 때 명령어를 덮어쓰기 힘듬
					
					CMD ["java", "-jar","app.jar"]
				
				=>	ENTRYPOINT ["java", "-jar"]		# 고정되는 실행
					CMD ["app.jar"]						# 변경가능한 실행
	
	7) EXPOSE
	
		- 문법 : EXPOSE <port> [<port>/<protocol>...]
		
		- 용도 : 컨테이너가 사용하는 포트가 뭔지 알려주는 용도로 사용됨 (문서화)
					실제 port를 사용할 수 있게 open(public) 하지 않음.
					실제 사용하기 위해서는 명시적으로 Port-Fowading (ex. -p 1234:80)지정해 줘야 한다.
					
	8) ENV
	
		- 문법 : ENV <key>=<value> [<key>=<value>...]
		- 용도 : 환경변수 설정
					docker run 할때 ENV값 덮어쓰기 가능한. ( ex. -e MYSQL_DATABASE=testdb)
					
	9) VOLUME
	
		- 문법 : VOLUME ["/data"]
				
		- 용도 : 컨테이너의 변경사항을 유지하는 목적임
			ex.
					FROM ubuntu
					RUN mkdir /myvol
					RUN echo "hello world" > /myvol/greeting
					VOLUME /myvol

//////////////////////////////////////////////////

https://docs.docker.com/reference/compose-file/services/ 참조

1. 개념 
	: 여러개의 컨테이너(서비스)를 한번에 정의하고, 한번에 실행/중지/삭제가 가능하도록 지원하는 도구.
	
2. 파일명 :
	  docker-compose.yaml/yml
	  compose.yaml/yml
	  
3. 특징
	- 필요할때 Dockerfile 사용가능.
	- 자동으로 동일한 네트워크로 묶인다 (****)
	- 여러 컨테이너를 한번에 시작 및 종료 할 수 있다
	- depends_on: 속성으로 컨테이너 실행 순서를 지정가능
	
4. docker compose 기본구조

	------------------------------
	services:			# 최상위 속성
	  web:				# 서비스명 ( 임의의 값 ), 하나의 컨테이너가 됨
		 image: nginx:latest		# base image 명
		 ports:						# Port Forwarding / -p 8080:80 과 동일
			- "8080:80"
		 depends_on:				# db를 먼저 실행하고 실행할것
			- db

	  db:					# 서비스명 ( 임의의 값 ), 하나의 컨테이너가 됨
		 image: postgres:18		# base image 명
		 environment:				# 환경변수, / Dockerfile: ENV SERVER_PORT=8080
			POSTGRES_USER: example			# key값은 대문자로 지정(관례)
			POSTGRES_DB: exampledb			
		 volumes:					# 영속성 위한 볼륨. -v 볼륨명:/var/lib/mysql
			- type: bind
			  source: ./proxy/nginx.conf
			  target: /etc/nginx/conf.d/default.conf
			  read_only: true
	------------------------------

5. 문법정리 

	1) services 속성
		- 최상위 속성 
		- 하위에 여러 서비스를 가질 수 있음.
		  각 서비스는 하나의 컨테이너라고 할 수 있다.
		  
		- 구성
			services:
				서비스:		# 하나의 컨테이너
					imager:	[<registry>/] [<project>/] <image> [:<tag>|@<digest>]
								# 사용할 docker 이미지(base image), 없으면 다운로드
								# hub에서 제공하는 offical image 또는 Dockerfile 로 만든 커스텀 이미지
					
					build: 	# Dockerfile에서 직접 이미지 생성
						
			ex.	sample12_TodoApp2_SpringSecurity>docker build -t my-front-app:v1 -f My_Dockerfile .
				backend:
					image: my-front-app:v1
					build:
					  context: sample12_TodoApp2_SpringSecurity	# dockerfile이 위치한 폴더
					  dockerfile: My_Dockerfile
				
					container_name:	# 컨테이너이름, --name spring-mysql-demo4
					command:				# 명령어. Dockerfile의 CMD, 덮어쓰기 가능
											ex. command: /bin/sh -c 'echo "hello $$HOSTNAME"'
											==> 컨테이너 실행시 SHELL에 접속해서 '명령어(문자열)'를 실행하라
												 ( 명령어가 문자열이면 반드시 -c )
												 
					entrypoint: 		# 명령어. Dockerfile의 entrypoint와 동일, 덮어쓰기 불가
					ports:				# 포트포워딩(포트매핑). -p 8080:80 동일
					expose:				# 포트 문서화. Dockerfile의 EXPOSE와 동일
