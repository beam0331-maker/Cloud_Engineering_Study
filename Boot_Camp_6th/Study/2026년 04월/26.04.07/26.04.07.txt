3. 다형성( Polymorphims )

	1) 상속이 전제되는 스킬
		가. super 키워드
		나. 오버라이딩(Overriding)
		다. 다형성( Polymorphims )
		
	2) 개념: 하나의 참조변수가 타입이 다른 여러 인스턴스(자식타입)를 참조(관리)하는 능력.
		목적: 부모 타입의 변수 하나로 모두 관리하자. ( 재사용성 )
		ex. 
			반드시  A와 B, A와 C간의 상속관계 전제됨.
		
			A a = new A();
			  a = new B();
			  a = new C();
			
			B b = new A(); // 오류, 작은 타입에 큰 타입을 참조할려고함.
			
			A(부모, 큰타입) - B(자식, 작은타입)
								 - C(자식, 작은타입)
			
			////////////////////////////////////
			기본형( 큰타입 = 작은 타입 )
			byte b = 10;
			int n = b;
			////////////////////////////////////
			
	3) 다형성 활용
	
		가. 배열
			- 같은 타입만 저장가능
			- 다형성을 적용하면 모든 데이터를 저장 할 수 있음.
				ex. Employee 타입으로 배열을 만들면, 이 배열에 Manager와 Engineer 타입 저장가능
					 확장하면 Object 타입으로 배열을 만들면, 자바의 모든 데이터 저장가능.(**************)
		
		나. 메서드 파라미터 타입 (************)
		
				public static void method2(Employee e){}
				
				// 참조형
				method2(new Employee("홍길동", 2000));
				method2(new Engineer("이순신", 4300, "자바"));
				method2(new Manager("유관순", 4000, "관리"));
				
	4) 동적 타이핑(dynamic typing, dynamic binding)	// 다형성에서는 중요한 내용이다.
		개념: 컴파일 시점에 알고 있는 메서드와
				실행시점에 알고 있는 메서드가 동적으로 변경된다는 개념임.
				
				ex.
					public class Employee{
						...
						public void a(){
							sysout("employee");
						}
					}
					
					public class Manager {
						...
						@Overriding
						public void a(){
							sysout("Manager");
						}
					}
					
					Employee e = new Manager("유관순",4000,"관리");
					e.a()	// Manager 객체의 오버라이딩 메서드로 접근한다.
							// 컴파일 단계에서는 Employee의 메서드로 인식하고
							// 실제 실행시에는 Manager의 메서드로 실행
					e.b();// 오류 -> 부모 클래스로 생성된 자식 클래스는
							// 부모 클래스에서 오버라이딩된 메서드만 사용가능.
							
	5) 부모에 없고 자식에서만 추가된 변수 또는 메서드를 참조하기 위해서는
		반드시 자식타입으로 형변환해야된다. ==> 다형성을 포기한다...? 유연한 객체 사용과는 거리가 멀다
		
			작은타입 = (작은타입)e;
			ex.
			Manager m1 = (Manager)e;
			m1.b();
			System.out.println(m1.name);
			
	6) 다형성을 적용한 경우, 실제 new 한 타입인지 확인하는 연산자
		
		문법: 변수명 instanceof 타입명	// 리턴을 true/false
		ex.	e instanceof Engineer

1. package와 import
	
	1) package
	
		용도: 클래스 파일 관리 ( 원도우 폴더와 비슷한 기능 )
		문법:
			package 패키지명;
			package 패키지명.sub패키지명...;
			
		특징: 
		- 중복되지 않도록 유일한 값을 지정. ( 관례적으로 도메인, ex. google.com)
		  도메인을 거꾸로 지정해서 사용가능.
			ex. package com.goole;
		- package 지정하지 않으면 defaule 패키지로 처리됨
		- 패키지가 다르면 클래스들간에 접근이 불가 ==> import를 통해 해결가능
		- Java API(만들어진 클래스)들도 모두 패키지로 제공됨. ex. java.lang, java.io, java.util, ...
		  따라서 Java API 클래스를 사용하기 위해서는 패키지가 서로 다르기 때문에 반드시 import해야 된다.
		  단, java.lang은 import 안해도 된다. ( import안해도  사용가능한 유일한 패키지 )
		
		- 패키지가 다르면 동일한 클래스명 지정가능
		- 단 한번 지정
		
	2) import
		
		용도: 서로 다른 패키지에서 클래스를 접근하는 방법 ( 클래스가 있는 경로 지정 )
		문법:
				import 패키지명.클래스명;
				import 패키지명.서브패키지.클래스명;
				
		특징: 
		- import문 여러번 사용 가능
		- import문 없이 직접 패키지명 지정 가능
		  ex.
			- import p1.MyHello;
			- java.util.Random r = new java.util.Random();  
				
2. 접근지정자 (access modifier)
	
	용도: 클래스간의 접근을 제한하는 방법
	
	4가지 레벨:

					|  같은클래스	|	같은패키지 다른클래스  |  다른패키지 상속관계  |  다른패키지의 다른클래스
	____________|______________|_________________________|_______________________|__________________________
	public		|		가능	 	|				가능			  |			가능			  |				가능
	protected	|		가능		|				가능			  |			가능			  |				불가
	(default)	|		가능		|				가능			  |			불가			  |				불가
	private		|		가능		|				불가			  |			불가			  |				불가
	
	
3. 추상클래스 ( abstract class )

	1) 문법:
			public calss 클래스명{  <== concrete class (어떤 기능처리를 할지 구체화 되어 정해져 있는 클래스, 완성된 클래스)
				# 구성요소
				  - 변수, 생성자, 메서드( concrete method )
			}
			
			public abstract class 클래스명{ <== abstract class (어떤 기능처리를 할지 아직 구체화되지 않은 클래스,  미완성 클래스)
				# 구성요소
				  - 변수, 생성자, 메서드, 추상메서드( abstract method )				
			}
			
	2) concrete method vs abstract method
		
		concrete method: public 리턴타입 메서드명([파라미터, ... ]){ 동작구현 }
		
		abstract method: public abstract 리턴타입 메서드명([파라미터, ... ]);
							  ==> 메서드 동작이 아직 미정인 상태
							  // abstract 생략 불가
							  
							  
	3) 특징
		- 추상클래스는 미완성 클래스이기 때문에 직접 new 불가.
		  따라서 미완성 클래스 -----> 완성클래스로 만든 후에 사용해야 된다.
		
		- 추상클래스는 반드시 추상메서드 포함하지 않아도 된다
		  하지만 추상메서드를 포함하면 반드시 추상클래스로 만들어야 된다. ( 틀릴시 오류발생 )
		  
		- 추상메서드에서 abstract 키워드 필수 ( 생략불가 )
		  나중에 배울 Interface에서는 생략 가능.
		  
		- 단일상속(single inheritance)
		- UML은 삼각형 + 실선
		- 추상 메서드는 UML표기법에서 이탤릭체로 표기됨
		  
	4) 완성된 클래스로 만드는 방법
		=> 상속 + 오버라이딩메서드 이용
		
		ex. 
			(큰 타입) 추상클래스 public abstract void a();
				 △
				 |
				 |
				 | extends
				 |
			(작은 타입) 클래스 ( concrete 클래스)
							public void a(){}	# 추상클래스의 추상메서드는 **반드시 재정의**해야됨. (강제성 부여)
													// 오버라이딩과의 차이성 
													// 휴먼 에러로 인해 오버라이딩이 누락을 해결 가능
				클래스 s = new 클래스();
				추상클래스 s = new 클래스(); // 다형성 적용 가능
				
	5) 추상클래스 용도
		- 하위 클래스들에서 사용하는 메서드를 일치시키기 위한 목적. ( 통일성 )

4. 인터페이스 (interface) - 매우 중요함(***********************)
	
	1) 문법:
		public interface 인터페이스명{
			# 구성요소 4가지
			  - 상수
			  - 추상메서드 ( abstract 생략가능 )
			  - default 메서드
			  - static 메서드
		}
		
		저장파일명: 인터페이스면.java
		
		
	2) 구성요소
		
		가. 상수(final)
				
			int NUM = 20; 
			// 자동으로 public static final이 지정됨.
			// public static final int NUM = 20;
			// 인터페이스명.NUM 으로 접근가능하다. => static이 지정되어 있긴때문에 클래스 변수와 같이 취급
			
		나. 추상메서드 // 인터페이스를 사용하는 주된 이유.
				
			void a();
			// 자동으로 public abstract가 지정된다. 
			// public abstract void a(); 와 동일하게 인식한다.
			// abstract 생략 가능
				
		다. default 메서드
			
			문법: public default 리턴타입 메서드명(){ // 기능 구체화 } ==> concrete 메서드
			특징: 동작은 concrete 메서드처럼 동작됨. => new로 인스턴스화 하고 사용 가능.
		
		라. static 메서드
		
			문법: public static 리턴타입 메서드면(){ // 기능 구체화 }
			특징: 
			- 동작은 일반적인  static 메서드처럼 동작된다.
			- new 없이 인터페이스명.메서드명 호출(클래스명.메서드명) ==> 일반적인 static 메서드 호출과 동일하다
	
	3) interface 특징:
		- 불완전한 객체이기 때문에 직접 new 불가능
		  따라서 불완전한 객체 -------------------> 완성 클래스로 만든후에 사용해야 된다.
		- 다중구현가능: 상속과 다르게 하나의 클래스는 여러개의 인터페이스와 구현관계가 가능하다.
		- 인터페이스간의 상속이 가능하며, 다중 상속이 가능하다. 
		- implements 받은 concrete 클래스는 반드시 인터페이스의 추상 메서들 재정의해야 됨(강제성 부여)
		- 다형성 적용 가능
		- 추상메서드 작성시 abstract 키워드 생략 가능
		- 타입크기는 인터페이스 > 클래스(구현관계)
	
	4) 완성된 클래스로 만드는 방법
		==> 구현(implements)	+ 오버라이딩 메서드
			// 구현관계의 UML: 점선 + 삼각형이다
			
			
					 인터페이스 ------- 인터페이스		
										|																	
										| 상속관계(다중상속)
										| extends
										|																
 클래스 B  인터페이스1  인터페이스2: public abstract void a()
					△
					|
					| 다중구현 가능
					| implements 키워드
					|
		클래스 A (concrete 클래스)
			반드시 public void a(){} 재정의 필수.
