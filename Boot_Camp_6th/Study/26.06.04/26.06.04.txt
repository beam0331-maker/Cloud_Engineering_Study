	1) 이미지 보기
	
		- 개념 : 로컬에 저장된 Docker 이미지 목록 조회.
		- 문법 : docker image ls [OPTIONS] [REPOSITORY[:TAG]]
					
					docker image list
					docker images	( 가장 많이 쓰임 )
					
		- 옵션
			-a, --all : 모든 이미지 포함해서 조회 ( untaged, dangling 이미지는 기본적론 숨겨져있다 )
							# untaged 이미지 
							  : 하나의 이미지를 docker tag 명령어로 리눅스의 하드링크처럼 여러버전을 만들 수 있음. 이 경우에 특정 버전을 삭제하면 진짜 이미지가 삭제되는 것이 아니고 untageed 상태로 남게 된다.
							  
							# dangling 이미지
							  : 동일한 이미지(이미지:tag 가 같은경우)를 다시 빌드 할때, 기존 이미지가 tag를 잃게 되 상태의 이미지를 의미한다. <none>:<none> 포맷을 가진다.
			
			-q, --quiet : 이미지 ID만 출력
			--no-trunc	: 정보를 절삭하지 말고 전체출력
			--digests	: Docker hub에 있는 이미지 식별자
			-f, --filter: 조건으로 필터링 가능
							  https://docs.docker.com/reference/cli/docker/image/ls/#filter 
							  ex. docker images -f "before=nginx:latest"		
								   docker images -f "since=nginx:latest"
			--format		: 출력 형식 지정
							  https://docs.docker.com/reference/cli/docker/image/ls/#format  참조할것
							  기본은 table
							  
							///////////////////////////////////////////////////////////////////////////
								다음과 같은 속성 사용 가능.
								Placeholder			Description
								-----------------------------
								.ID					Image ID
								.Repository			Image repository
								.Tag					Image tag
								.Digest				Image digest
								.CreatedSince		Elapsed time since the image was created
								.CreatedAt			Time when the image was created
								.Size	Image			disk size
							///////////////////////////////////////////////////////////////////////////
								ex. docker images --format "table {{.ID}}\t{{.Repository}}\t{{.Tag}}"
				
		# 실습
		
			docker image ls
			docker image ls -a
			docker images
			docker image -a
			
			> docker images -q
			f979dcfed4c
			5aca99593157

	2) 이미지 세부 정보( metadata) 조회
	
		- 개념 : 로컬에 저장된 Docker 이미지의 세부 정보(metadata) 조회.
		- 문법 : docker image inspect [OPTIONS] IMAGE [IMAGE...]		# 별칭 존재하지 않음
					docker inspect				
		- 옵션
			--format		: 출력 형식 지정
							  https://docs.docker.com/engine/cli/formatting/ 참조할것
							  기본은 table
			
			ex. 
				docker image inspect nginx		# tag를 달지 않으면 latest tag가 매핑된다.
				docker inspect nginx hello world
				docker inspect nginx
				
				docker inspect nginx -f "{{.Id}}"
				docker inspect nginx -f "{{.Config.ExposedPorts}}"
				
			
		
		# 실습
			
			> docker image inspect nginx		# tag를 달지 않으면 latest tag가 매핑된다.
			> docker inspect nginx
			
			
		   > docker inspect nginx -f "{{.Id}}"     
			sha256:5aca99593157f4ae539a5dec1092a0ad8762f8e2eb1789085a13a0f5622369f6
			
			> docker inspect nginx -f "{{.Config.ExposedPorts}}"
			map[80/tcp:{}]
			
			> > docker inspect nginx -f "{{.Id}}  {{.Config.ExposedPorts}}"
			sha256:5aca99593157f4ae539a5dec1092a0ad8762f8e2eb1789085a13a0f5622369f6  map[80/tcp:map[]]

		- 개념 : 기존 이미지에 새로운 이름(tag 추가)을 부여하는 명령어.
		
		- 특징 : image ID는 동일하다 ( ****** )
					단지 이름만 다르다.
					
						ex.
							|nginx:latest (원본)
							|		|
							|		|
							|	이미지 ID: a123456789
							|		|
							|		|
							|my-nginx:v1	(별칭)
		
		- 문법 :	docker image tag SOURCE_IMAGE[:TAG] TARGET_IMAGE[:TAG]
					docker tag
		- 용도 : 버전관리(ex. v1, v2) 및 프로파일(ex. prod, dev, text )관리용
					docker bub에 업로드 할때 주로 사용한다. ( 업로드할때 이름이 정해져 있기때문 )
		
		# 실습

	5) docker image 삭제
		
		- 개념 : 로컬에 있는 docker image 삭제
		
		- 특징 : 컨테이너로 실행 중이면 삭제 불가.
					반드시 실행 중인 컨테이너를 중지하고 삭제하고, 나중에 image 삭제 가능
					
					
		- 문법 : docker image rm [OPTIONS] IMAGE [IMAGE...]		# 이미지 ID, 이미지명:tag
					docker image remove
					docker rmi		(***)
					
		- 옵션
			-f, --force	: Force removal of the image
			--no-prune	: 
			
		# 실습
			
			> docker rmi 0e760fdfbc48			# hello-world:latest image ID로 삭제
			Untagged: hello-world:latest		# image ID에서 TAG가 끊겼다
			Deleted: sha256:0e760fdfbc48ba8041e7c6db999bb40bfca508b4be580ac75d32c4e29d202ce1
			
			> docker images
			IMAGE               ID             DISK USAGE   CONTENT SIZE   EXTRA
			nginx:1.30-alpine   5f979dcfed4c       93.6MB         26.9MB        
			nginx:latest        5aca99593157        241MB           66MB        
			nginx:v1            5aca99593157        241MB           66MB        
			nginx:v2            5aca99593157        241MB           66MB 
			
			> docker rmi 5aca99593157			# nginx image ID로 삭제, TAG가 여러개인 경우  ==>  삭제불가
			Error response from daemon: conflict: unable to delete 5aca99593157 (must be forced) - image is referenced in multiple repositories					
			# multiple repositories ==> 여러 이름(TAG)로 참조되어 있다.
			
			> docker rmi nginx:1.30-alpine		# image 이름으로 삭제
			Untagged: nginx:1.30-alpine
			Deleted: sha256:5f979dcfed4ce6461873f087e8c980d6e29b084b9e8776d9704a7e989b5f4898
			
			# 동일한 이미지 ID를 가진 TAG가 여러개인 경우는 이미지영으로 삭제
			> docker rmi nginx:v1                   
			Untagged: nginx:v1		#		실제 삭제가 아니라 TAG만 끊긴다
			> docker images
			IMAGE          ID             DISK USAGE   CONTENT SIZE   EXTRA
			nginx:latest   5aca99593157        241MB           66MB        
			nginx:v2       5aca99593157        241MB           66MB 
			
			> docker rmi nginx:v2         
			Untagged: nginx:v2
			
			# ID를 공유하는 TAG가 유일하기 때문에 이름으로 삭제해도 Deleted된다
			> docker rmi nginx:latest
			Untagged: nginx:latest
			Deleted: sha256:5aca99593157f4ae539a5dec1092a0ad8762f8e2eb1789085a13a0f5622369f6

	8) docker hub에서 docker image 내려받기
	
		- 개념 : Registry(docker hub)에서 Docker 이미지를 로컬에 다운로드하는 명령어
					인증이 필요없다  ==>  누구나 다운로드 가능
					
		- 특징 : 다운로드만 되고 실행은 안된다		# docker run ==> image 실행(컨테이너), 없다면 다운로드 후 실행
		
		- 문법 : docker image pull [OPTIONS] NAME[:TAG|@DIGEST]
					docker pull
		
		- 옵션
			-a, --all-tags	: 저장소에 있는 모든 이미지 다운로드 ( tag가 다른 이미지 포함 )
			-q, --quiet		: 이미지 다운로드할 때 상세정보 출력 안함
			
		# 실습
			
			> docker pull ubuntu
			> docker images
			IMAGE                ID             DISK USAGE   CONTENT SIZE   EXTRA
			hello-world:latest   0e760fdfbc48       25.9kB         9.49kB        
			nginx:latest         5aca99593157        241MB           66MB        
			ubuntu:latest        f3d28607ddd7        160MB         45.3MB  
			
			> docker pull -q ubuntu:24.04
			> docker pull -q ubuntu@023f8a753c22

	10) 이미지 업로드
	
		- 개념 : 로컬에 있는 Docker 이미지를 registry(docker hub)에 업로드하는 명령어
		
		- 특징 : docker hub에 있는 저장소 이름과 로컬에 있는 이미지명이 동일해야됨(*****)

		- 문법 : docker image push [OPTIONS] NAME[:TAG]
					docker push
		
		- 옵션
			-a, --all-tags	: 로컬에 있는 모든 이미지 업로드 ( tag가 다른 이미지 포함)
			-q, --quiet		: 이미지 업로드할 때 상세정보 출력 안함
			
		# 실습
		
			가. hub.docker.com에서 로그인
			나. 저장소 생성

1. container 명령어
	
	- 특징 : 읽기/쓰기 가능 (read/write)
				하나의 이미지에서 여러 개 생성가능, 실행은 하지 않는다
				휘발성( 컨테이너에서 했던 모든작업들은 일시적임)
				==>  볼륨(volume) : 컨테이너 수정작업들은 파일에 저장해서 영속성을 얻어야 한다
				
				외부에서 직접 접근이 불가( 해결 : 포트매핑(port forwarding) -p 외부포트:내부포트 )
	
	1) 컨테이너 생성
	
		- 개념 : 로컬에 있는 Docker 이미지를 사용하여 컨테이너를 생성
		
		- 문법 : docker container create [OPTIONS] IMAGE [COMMAND] [ARG...]
					docker create
		
		- 옵션
			--name			: container 이름 ( 지정하지 않으면 랜덤 )
			-p, --publish	: 포트매핑
			-e, --env		: 환경변수 설정 ( key=value로 하나씩 설정 )	
			--env-file		: 환경변수 설정 ( 환경변수 파일 읽어오기 )
			-v, --volume	: 볼륨연결 ( host의 임의파일과 연결 )
			--network		: 동일한 네트워크(Docker 내부의 네트워크)로 묶기 위해서 (****)
								  => 컨테이너는 기본적으론 독립적이지만 같은 네트워크로 묶어 서로 접근가능
			
			-t, --tty		: 모니터
			-i, --interactive	: STDIN( 표준 입력 - 키보드 )
			==> -it	:  컨테이너에 접속시 사용하는 옵션
			
			-a, --attach	: Attach to STDIN, STDOUT or STDERR
			
			
		
		# 실습 . --name		
			> docker create --name my-nginx nginx
			49947fb80b506498352397663fea9d53a6c62cc8a2ff72628125572bddcb2259
			
			> docker ps -a                       
CONTAINER ID   IMAGE     COMMAND                  CREATED          STATUS    PORTS     NAMES
49947fb80b50   nginx     "/docker-entrypoint.…"   20 seconds ago   Created             my-nginx

		# 실습 . -p ( 포트 포워딩 )		
			> docker create --name my-nginx2 -p 1234:80 nginx
			72f2b51cc43c3fb0b70ae21ad73b542c2e473141f94194d9fdc752c23adbed71
		
		# 실습 . -e ( 환경변수 )
			> docker create --name some-mysql -e MYSQL_ROOT_PASSWORD=1234 mysql:8.3
		
		# 실습.  -v ( volume)
			> docker run --name some-mysql2 -v /my/own/datadir:/var/lib/mysql -e MYSQL_ROOT_PASSWORD=1234 -d mysql:8.3
			a615e62ec66516ed77b091b050cd5eee769c890d603ed1b6fd1900967f51a683
			
			> docker inspect some-mysql2
		
		# 실습. --network ( 돌려보지 말것. 이미지가 설치되지 않아 작동하지 않는다 )
			> docker network create full-stack		# 네트워크를 생성한다.
			> docker create --name my-nginx3  --network full-stack mysql
			> docker create --name my-nginx4  --network full-stack myboot
			> docker create --name my-nginx5  --network full-stack myvuejs
			
			
		# 실습. -it 옵션		: 실제 컨테이너에 접속할 때 사용하는 옵션.
		# 		. Command 옵션	: 현재는 어플을 실행할때 shell을 활성하라는 명령어
			> docker create -it --name my-nginx nginx sh			# 쉘: ubuntu --> bash / nginx  --> bash
			> docker create -it --name my-ubuntu ubuntu bash		# 나중에 start하면 bash로 접속
			
			> docker ps -a 		# STATUS값이 Created 임. 실행은 안됨
