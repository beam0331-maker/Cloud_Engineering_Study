	# 각 역할 정리
	- DispathcerServlet: 모든 요청을 처리 (Front Controller Pattern)
	- HandlerMapping: 요청URL을 분석하여 요청처리를 담당하는 Controller 메서드 선택
	- Controller: 서블릿/JSP 버전에서 서블릿 역할 담당.
					ex. 사용자 입력데이터 처리, 음답처리(Model View 처리)				
	
	- Service: 로직과 트랙잭션처리
	- Repository: DB연동
	- ViewResolver: 논리적이름(ex. list)을 이용해서 
						 실제처리되는 View완성(ex. list.html)

3. @RequestMapping 저리

	1) 용도
		요청 URL( http://서버IP:포트번호/컨텍스트명/서블릿맵핑/요청매핑값 )에서
		/ 요청매핑값을 추출해서 일치하는 Controller의 메서드를 선택하는 용도
			
	2) 다양한 패턴이 제공
	
		@RequestMapping("/hello") # 단일요청, 정확하게 일치해야됨
		@RequestMapping(value = "/hello") # 단일요청, 정확하게 일치해야됨
		
		@RequestMapping(value = {"/hello2","/hello3"}) # 멀티요청, 정확하게 일치해야됨
		@RequestMapping(value ="/yyy*") # 특정값으로 시작( ex. yyy33, yyy111 가능 ) 
		@RequestMapping(value ="/zzz/*") # 특정경로 하나 ( ex. zzz/, zzz/ccc, /zzzz/ccc/ddd(404 오류))
		@RequestMapping(value ="/xyz/**") # 특정경로 여러개 ( ex. xyz/, xyz/ccc, /xyz/ccc/ddd)
		
		@RequestMapping(value ="/aaa/*/bbb") # 중간에 특정경로 하나 ( ex. aaa/eee/bbb, aaa/ccc/bbb)
		
		@RequestMapping(value ="/ccc/**/ddd") # 중간에 특정경로 dufjro ( ex. ccc/x/d/ddd)
		
		# 요청뿐만 아니고 다음과 같이 mybatis  mapper 등록할때도 사용이 가능하다.
		mybatis:
			mapper-locations: com/exam/config/**/*.xml
		
		
	
		반드시 다음과 같이 설정해야 된다
		'spring.mvc.pathmatch.matching-strategy=ant_path_matcher'
		
		  mvc:
    pathmatch:
      matching-strategy: ant_path_matcher

	2. Controller 작업
	
		가. 화면보는 요청 (GET 요청)
		
		  //1. GET 요청 처리하는 코드
		 // @RequestMapping(value = "/memberForm")
		 @RequestMapping(value = "/member", method = RequestMethod.GET) // GET 방식으로 요청
		 public String memberGET(){
			  System.out.println("memberGET");
			  return "memberForm";
		 }
		
		나. 실제 처리하는 요청 (POST 요청)
		
		@RequestMapping(value = "/member", method = RequestMethod.POST) // POST 방식으로 요청
		 public String memberPOST(){
			  System.out.println("memberPOST");
			  return "memberForm";
		 }
		 
		중요한 점은 GET과 POST의 요청매핑값이 /member로 동일함. method방식으로 구별됨.
