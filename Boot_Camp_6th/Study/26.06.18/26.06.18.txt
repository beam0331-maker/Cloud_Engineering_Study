7장. K8s 네트워크
/////////////////////////////////////////

1. 개념
	- 클러스터 내의 모든 pod를 하나의 네트워크로 묶어서 관리하는 구조
	- Node 단위가 아닌 클러스터 단위의 네트워크이다 
	  ==> Node는 pod가 실행되는 머신뿐일 뿐이다. 
	
	--------------------------------------
	가능한 이유:
	쿠버네티스는 CNI 플러그인이 노드 간에 VPN과 유사한 터널링을 구성하기 때문에, 
	물리적으로 다른 네트워크에 있는 파드끼리도 사설 IP로 직접 통신이 가능하다.
	CNI가 터널링으로 오버레이 네트워크를 구성해서 하나의 가상 네트워크처럼 동작하기 때문에 별도의 라우팅 설정 없이 어떻게 서로 다른 네트워크 간 통신이 가능
	
	아래 터널링 방식을 이용해서 통신한다.

	All cluster nodes form a mesh of tunnels using the UDP-based encapsulation protocols VXLAN or Geneve. 

	https://docs.cilium.io/en/stable/network/concepts/routing/
	--------------------------------------		

2. K8s의 네트워크 규칙 
	
	1) 모든 Pod는 고유한 IP를 갖는다.
	2) 모든 Pod는 NAT 없이 통신이 가능해야 된다.
	3) Node 에서 Pod를 접근할 수 있어야 된다. ( Pod IP 이용 )
	4) Pod에서 외부접근이 가능해야 한다

3. K8s 일반적인 통신 형태  

	1) WWWW 통신 ( 기본적으로 가능 )
	
		pod -------------------> 인터넷
		
	2) Pod와 Pod 통신 ( 기본적으로 가능 )
		- 각 Pod가 Node가 달라도 가능( ***** )
		  NAT, Port forward 등 추가 기능이 필요 없음 ( **** )
		
		- 권장하지 않음 ( Pod ip는 고정이 아니다, node에 따라 Pod가 죽었다 살아나면 ip도 변경됨 )
			ex.
						Pod ip 이용
				Pod -----------------------> Pod
			
	3) Pod와 Service 통신( 일반적인 방법 ) 
				  
		 Service 이름 이용		label로 접근
		Pod ---------> Service -----------> Pod
		
		- pod ip 대신 Service 이름으로 통신
		- Pod는 Service에 이름으로 접근하고, Service는 label을 통해 pod에 접근한다
		  ==> pod의 ip가 바껴도 네트워크를 유지할 수 있다
		  
	4) 외부에서 Pod 접근 ( 추가작업 필요 )
		
		- K8s 에서 기본적으로 Pod ip를 활용해서 직접 접근이 불가능함. ( ***** )
		
		- 추가 작업:
			- 포트포워딩
			ex. kubectl port-forwad TYPE/NAME
			
			- Service 이용

8장. Service
/////////////////////////////////////////
https://kubernetes.io/docs/concepts/services-networking/service/

1. 개념
	- Pod는 외부에서 직접 접근이 불가능 하기 때문에 Service를 통해 Pod에 접근할 수 있음
	
2. 용도 2가지 
	
	1) Pod를 외부에서 접근하도록하기 위함
	
	2) Pod와 Pod간 연동할 때, Pod IP는 변동될 수 있기 때문에 고정된 값을 가진 Service를 사용함
	
3. 역할
	
	1) 고정 IP 역할 
	2) DNS 제공						K8s의 CoreDNS
		ex. http://hello-service	--------------->	IP 번호
	3) 로드 밸런싱(Loal Balancing) 역할
	
4. Service가 Pod 선택
	
	# service yaml 샘플
	
	apiVersion: v1				# API Version
	kind: Service				# 리소스 종류
	metadata:					
	  name: my-service			# 서비스 명
	spec:
	  selector:							
		app.kubernetes.io/name: MyApp		# app.kubernetes.io/name: MyApp 값으로 설젇정된 라벨의 Pod 선택( 여러 Pod 선택 가능)
	  ports:												
		- protocol: TCP
		  port: 80				# Service의 포트 
		  targetPort: 9376		# Service가 접근하는 Pod의 포트 
	  type: ClusterIP
	  
	가. Pod ( label 이용 ) 
		labels:
		  x: y
	
	나. Service ( selecctor 이용 )		
		spec:
		  selecctor:
		    x: y

			- type: 을 지정하지 않았을때 default 이다
			
		나. 구조
		
		--------------------------------------------------- 클러스터 
				  호출( pod ) : front-end(Vue.js)
				   |
				Service (svc)
				
	
		  pod 	  pod 	  pod	: back-end ( SpringBoot )

			  type: ClusterIP			# 클러스터 내부에서만 Service 호출 가능
