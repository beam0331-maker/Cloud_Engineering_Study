1. 프로파일(Profile)

	1) 개념
		: 개발할 때는 다양한환경이 존재함( ex. 개발환경, 프로덕션 환경, 테스트환경,...)
	
	2) 
		문법1:
		
		기본: application.yml
				application-프로파일명.yml
				
		ex.	applicaiton-dev.yml
				application-pord.yml
				
		최정파일:
			application.yml		<== 공통적으로 사용하는 설정저장
			application-dev.yml	<== 개발시 사용하는 설정저장
			application-prod.yml	<== 프로덕션시 사용하는 설정저장
			
		문법2: Bean도 관리 가능
		ex.
		
		@Component
		@Profile("prod")
		public class PordClass {
			 public PordClass() {
				  System.out.println("PordClass");
			 }
		}
		
		@Configuration
		public class ProfileConfiguration {

			 @Bean
			 @Profile("prod")
			 public String creatProd(){
				  System.out.println("creatProd");
				  return "prod 관련 객체 생성";
			 }
		}
			
			
	3) 프로파일 활성화
		
			spring:
				prfiles:
					active: 프로파일명
					
		java 0jar myapp.jar --spring.profiles.active=prod

1. Spring JDBC
	
	1) 기존 JDBC
		- 명시적으로 Connnetcion 얻고 PreparedStatement로 SQL전송, Resultset 결과 처리.
		- 반드시 예외처리 필수( SQLExecption(비 런타임계열) 예외가 발생됨 )
		- 트랜잭션 처리가 까다롭다.
		
		===> 보일러플레이트 코드라고 부름.
		
		
	2) Spring JDBC 특징
		: JDBC 코드 단순화
			- close 불필요
			- 예외처리 불필요
			- 손쉬운 트랜잭션처리 (@Transactional 용)
			- ConnectionPool 자동 제공 
				ex. DBCP2	( Spring Framework )
					 Hikari	( Spring Boot )
					 
	3) JdbcTemplate 클래스 이용 ( <= MyBatis의 SqlSession 역할 )
		
		가. MyBatis 메서드
			
			- SELECT : selectOne()
						  selectList()
						  
			- INSERT : insert()
			- DELETE : delete()
			- UPDATE : update()
			
			- 트랜잭션 처리
				session.commit();
				session.rollback();
			
		나. JdbcTemplate 메서드
		
			- SELECT : queryForObject()	<== selectOne() 동일
						  query() 				<== selectList() 동일
						  
			- INSERT : update()
			- DELETE : update()
			- UPDATE : update()
			
			- 트랜잭션 처리
				@Transactional
	
	4) 의존성 설정( starter, *.jar)
		
		implementation 'org.springframework.boot:spring-boot-starter-data-jdbc'
