1. 클래스 관계( Class Relationship )
	
	개념: 생성된 객체간의 관계 의미
	
	1) has a (use a) 관계
		- 클래스들을 작성: 트럭, 엔진, 라디오, 학생, 컴퓨터, ...
		
		ex. 트럭 has a 엔진.	
			 트럭 has s 엔진.
			 
			 학생 has a 컴퓨터.
			
		- has a 관계를 자바코드로 표현하는 방법?
			인스턴스변수 형식을 표현하면 됨.
			
			ex. 트럭 has a 엔진
			
			public class Truck{
				Engine e;
			}
			public class Engine{
				...
			}
		- 종류 2가지	// 트럭에 엔진은 필수지만 라디오는 망가져도 트럭에 치명적인 영향은 안준다. 
			가. Composition(합성): 동일한 life cycle 갖는 경우
				 ex. 트럭 has a 엔진
				 UML은 채워진 마름모 표현(◆---->) 
				 
			나. Aggregation(집합): 서로 다른 life cycle 갖는 경우
				 ex. 트럭 has a 라디오
				 UML은 빈 마름모 표현(◇---->) 

				
		// uml도 찾아봅시다.
			 
	2) is a 관계
		- 클래스 작성: 고양이, 강아지, 애완동물, 학생, 중학생,....
		ex. 고양이 is a 애완동물
			 강이지 is a 애완동물
			 중학생 is a 학생
			 
		- is a 관계가 자바의 상속관계임( inheritance )임
		
		- 상속(is a) 관계를 자바로 표현하는 방법.
		  extends 키워드 사용
		  
			ex. 고양이(Cat) is a 애완동물(Pet)
				
				public class Pet{}
				public class Cat extends Pet {}
				public class Dog extends Pet {}
										
		- UML: ----▷ 
			ex.
					 자식		    부모
					고양이 ----▷ Pet
					
		- 부모의 데이터 타입이 자식보다 크다.
		- 자식클래스 간의 관계는 없다 ( Cat 과 Dog는 관계가 없다 )		
		- 단일상속( Single inheritance ): 자식은 하나의 부모만 상속가능하다 <== 계층 구조가 명확하다.
		- 상속관계(extends)가 명시되지 않은 클래스는 Object(최상위 클래스)를 상속 받는다.
		- 자식 클래스는 부모의 변수와 메서드를 상속받아 상속없이 사용가능. ==> 재사용성이 향상된다.
		- 상속 불가 2가지 
			가) 생성자: 부모의 생성자는 상속 불가
			나) private 속성들도 상속불가
		- 항상 자신보다 부모를 먼저 생성함 (***********************)
		  => 최상위 클래스(Object)가 가장 먼저 생성된다.
		  
		- 내부적인 메커니즘:
		- 자식 생성자에서 부모 생성자를 자동으로 호출함. 이때 자식은 super() 키워드를 통해 부모생성자를 호출한다.
		- 부모 생성자는 자동 호출되었을때 기본적으론 기본 생성자로 호출된다.
		- 명시적으로 호출가능 ( 반드시 자식생성자 첫라인에 호출해야 됨 )
		- 명시적으로 호출하는 이유는 부모에서 선언된 인스턴스 변수를 자식이 아닌 부모에서 초기화하기 위함.
		  
				부모클래스
					부모생상자 <-┐
									 |
									 | super()	// 자동으로 삽입됨, 명시적 호출 가능
				자식클래스 		 |	
					자식생성자 --┘
	
	3) 오버라이딩( Overriding ) 메서드 : 메서드 재정의 의미.
		개념: 부모의 메서드를 자식이 재정의해서 사용함.
		목적: 재사용성
		규칙: 메서드 이름 동일
				리턴타입 동일
				파라미터 동일
				접근지정자는 같거나 덜 제한하는 지정자
				(부모의 접근지정자: (default) --> 자식의 접근지정자: default, protected, public 지정가능)
		ex.	
				부모
					public void a(){}
					
					
				자식
					@Override // 어노테이션(annotation) : 오버라이딩 메서드에 지정하여 Overriding  메서드임을 알려주는 동시에
																	  오버라이딩 규칙에 위배되었을 때 오류가 발생되도록 지원함.
					public void a(){ //구현 내용 수정 }
		
		재정의 불가한 경우: 부모 메서드가 private.
								  부모 메서드가 static.
								  부모 메서드가 final
		
	4) super 키워드
		개념: 자식에서 부모를 호출할 때 사용.
		용도:
				가. 부모의 생성자 호출
					- 문법: super([파라미터]);
					- 자식 생성자의 첫라인에서 호출
					
				나. 부모의 멤버(변수, 메서드) 호출
					- 문법: super.멤버
					- 부모의 멤버는 상속관계이기 때문에 굳이 호출하지 않아도 자식에서 사용가능.
					- 목적: 부모에 있는 멤버가 자식에게도 정의되어 있을때 구분하기 위해.
					  
					  ex. 
							부모: String name;
									public void a(){}
									
							부모: String name;
									public void a(){}
									
									(this.)name <== 자식의 name 참조.
									(this.)a()	<== 자식의 a () 호출
									
									super.name  <== 부모의 name 참조.
									super.a()	<== 부모의 a () 호출
									
2. Object 클래스
	1) 개념: 최상위 클래스 ( 모든 클래스가 자동으로 상속받는 클래스이면서 가장 먼저 생성되는 클래스 )
		주요메서드: ...
					toString()
					
					Object의 실제 구현:
						public String toString(){
							return 패키지명.클래스명@16진수;	# 클래스의 주소값에 해당되는 문자열
						}
					
	2) toString()
		- 역할: 값을 문자열로 변환해주는 기능임.
		- 사용되는 경우: 참조변수를 콘솔에 출력하기 위해서 System.out.println(참조변수) 사용할 때 자동으로 호출되는 메서드임.
							  주소값(ex.100번지)을 콘솔에 출력하기 위해 문자열로 만들어줘야 하기 때문에 자동으로 toString() 호출됨.
		
			ex. 
				Cat c = new Cat();
				System.out.println(c);	# 참조변수 출력
				System.out.println(c.toString());
		- 결론:재사용 클래스를 만들 때 Object의 toString() 재정의해서 사용하자.
				 toString()메서드를 이용하면 재사용 클래스에서 추가 메서드가 필요 없어짐.

3. 다형성( Polymorphims )

	1) 상속이 전제되는 스킬
		가. super 키워드
		나. 오버라이딩(Overriding)
		다. 다형성( Polymorphims )
		
	2) 개념: 하나의 참조변수가 타입이 다른 여러 인스턴스를 참조하는 능력.
		목적: 부모 타입의 변수 하나로 모두 관리하자. ( 재사용성 )
		ex. 
			반드시  A와 B, A와 C간의 상속관계 전제됨.
		
			A a = new A();
			  a = new B();
			  a = new C();
			
			B b = new A(); // 오류, 작은 타입에 큰 타입을 참조할려고함.
			
			A(부모, 큰타입) - B(자식, 작은타입)
								 - C(자식, 작은타입)
			
			////////////////////////////////////
			기본형( 큰타입 = 작은 타입 )
			byte b = 10;
			int n = b;
			////////////////////////////////////
