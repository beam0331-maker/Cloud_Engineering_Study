5. 서블릿(Servlet)

	1) 특징
		- *.java
		- 저장위치는 src/main/java에 저장
		- 반드시 패키지 필수 (*)
		- main 메서드가 없음. 시작점이 없다.
		  ( 사용자가 맨 처음 요청하는 서블릿이 시작점이 된다. 유저는 다양한 루트를 통해 접근할 수 있다. )
		  
		- 직접 new하지 않음.
			Tomcat 서버가 필요한 시점에 생성부터 소멸까지 관리해줌
			Tomcat 서버가 필요한 이유: Servlet/JSP 같은 동적컴포넌트를 관리함
			
		- 실행결과는 html로 나옴
	
	2) 구현 방법 (*)
		
		가. 패키지로 구성
			ex. com.servlet
			
		나. extends HttpServlet ( jakarta.servlet.http 패키지 )
			
			////////////////////////////////////////////////////
			 서블릿의 계층구조 (외우기 *)
				
				Servlet, ServletConfig ( 인터페이스 )				
					|
				GenericServlet ( 추상 클래스 )
					|
				HttpServlet ( 추상 클래스 )
					|
				사용자 서블릿
				
				Servlet 인터페이스: init(), service(), destroy(), getServletConfig()
				ServletConfig 인터페이스 : getInitParametor(), getServletName(), getServletContext()
				GenericServlet 추상클래스 : init(), service(), destroy(), getInitParametor()
				HttpServlet 추상클래스 : doGet(), doPost(), doPut(), doDelete()
				
				https://tomcat.apache.org/tomcat-10.1-doc/servletapi/index.html
												
				==> 사용자 서블릿에서 위의 메서드를 사용 또는 재정의가 가능 (*)
		
			////////////////////////////////////////////////////		
		
		다. doGet(기본),doPost : 반드시 재정의해서 사용해야된다.(*)		
			 ( html에서 method = "get(기본)| post" )	
		
		라. 서블릿맵핑
			
			ex. 
				src
				|-main
					|-java
						|-com
							|-servlet
								|-HelloServlet
			
			요청: http://localhost:8080/컨텍스트명/servlet/풀패키지의서블릿명
					http://localhost:8080/hello/servlet/com.servlet.Helloservlet  ==> 현재 사용 안됨
					
					- 보안취향, URL이 길다
					
			==> [servlet/com.servlet.Helloservlet] 부분을 별칭을 준다 ==> 서블릿 맵핑
				 http://localhost:8080/hello/서블릿맵핑
				 
			# 서블릿 맵핑 방법 2가지
				
				가. 어노테이션 이용
					- @WebServlet("/서블릿맵핑")	# / 필수
					  @WebServlet("*.do") 			# 확장자패턴
					  
				나. web.xml
				
				<!-- 서블릿 맵핑 -->
				<servlet>
						<!-- servlet-name 태그를 통해 servlet과 servlet-mapping 태그를 연결한다 -->
					  <servlet-name>WorldServlet</servlet-name>
					  <servlet-class>com.servlet.WorldServlet</servlet-class>
				 </servlet>    
				 <servlet-mapping>
					  <servlet-name>WorldServlet</servlet-name>
					  <url-pattern>/World</url-pattern>
				<servlet-mapping>
			
				==> Spring Framework에서 내부적으로 사용되는 서블릿매핑 방법 (DispatcherServlet, / 으로 매핑)

6. 서블릿 LifeCycle
	- Tomcat 컨테이너가 Servlet의 LifeCycle(생성-소멸) 관리함.
	  생성 때 호출되는 콜백메서드 (시스템이 호출하는 메서드) 제공 : init()
	  소멸 때 호출되는 콜백메서드 (시스템이 호출하는 메서드) 제공 : destroy()
	  요청 때 호출되는 콜백메서드 (시스템이 호출하는 메서드) 제공 : doGet/doPost
	  
	1) init() 메서드
		- 서블릿이 생성될 때 자동으로 호출됨.
		- 한번만 호출됨 ==> 서블릿은 한번만 생성된다.
		 
	2) doGet/doPost 메서드 ( 서비스 메서드라고 부름 )	
		- 서블릿에 요청할 때 자동으로 호출됨.
		- 요청할 때 마다 매번 실행됨. (*)
		
		코드 구현:
			- doGet(HttpServletRequest request, HttpServletResponse response){}
			
			- doPost(HttpServletRequest request, HttpServletResponse response){}
		
			==> HttpServletRequest와 HttpServletResponse는 로컬변수이다
				 따라서 요청할 때마다 매번 새롭게 생성된다.(*** 가장 중요) // [이유 작성하기]
	
	3) destroy() 메서드
		- 서블릿이 삭제될 때 호출 ( 서버측에서 파일을 수정하며 재시작될때 이전 서블릿이 소멸되면서 새로운 서블릿이 생성된다 )
		- 단 한번 호출
		
	==> 서블릿은 한번만 생성되고, 여러 사용자 요청을 하나의 서블릿이 처리한다.(*)
	
	- 서블릿에서 선언하는 변수는 서블릿의 주기와 같이 하기 때문에 불특정 다수에게 노출된다.
	- 특정인의 요청에만 변수가 노출되게 하고 싶다면 doGet() 에서 선언해야 한다.
