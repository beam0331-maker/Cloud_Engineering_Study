		나. redirect 방식

				response.sendRedirect("target");

					response.sendRedirect("target.jsp");

				URL이 변경된다

								3) 응답("target.jsp 정보 포함")
								
								4) 요청( http://locahhost:8080/app8/RedirectServlet )
								HttpServletRequest 하고 HttpServletResponse 생성됨
								---------------------------------->	 target.jsp( 화면처리 )
								<----------------------------------  request.getAttribute("key"); // null
								5) 응답
				
				- [1) 요청]과 [4) 요청]에서 생성되는 HttpServletRequest, HttpServletResponse가 서로다름(**)
				- servlet - jsp 간의 데이터 전달은 session scope에서 이루어져야 한다.

		# 세션과 쿠키 비교 정리
			
			가. 세션
				- 서버에 데이터를 저장
				- 저장되는 데이터 종류는 모든 데이터 가능(Object)
				- 서버에 저장되기 때문에 보안 이슈가 거의 없음.
				- 서버에 저장되기 때문에 데이터 저장 크기 이슈가 없음.
					( 성능이 떨어지는 서버인 경우에는 이슈가 있음 )
				
			나. 쿠키
				- 클라이언트에 데이터를 저장
				- 저장되는 데이터 종류는 문자열만 가능 ( String )				
				- 클라이언트에 저장되기 때문에 보안 이슈가 있음.
				- 클라이언트에 저장되기 때문에 데이터 저장 크기 이슈가 없음. ( 과점에 따라서 달라짐 )
				- 사용자가 쿠키 사용을 비활성화 시킬 수 있음. ( 매우 큰 리스크 )
				- 도메인 당 3000개까지 생성가능. 크기 4kb
			
			실무에서는 세션과 쿠키를 같이 사용함

3. JSP ( Java Servet Page )

	1) 특징
		- 서블릿처러 동적 컴포넌트
		- *.jsp
		- 3단계로 실행됨.
			가. 변환단계
				test.jsp ----------> test_jsp.java
			나. 컴파일단계.
				test_jsp.java ----------> test_jsp.class
			다. 실행단계
				test_jsp.class ----------> html
				
	2) 구성요소
		
		가. html 태그
		나. JSP 태그
		
			- directive 태그
				* page directive		: <%@ page 속성명="속성값" ... %>
				* include directive	: <%@ include page 속성명="속성값" ... %>
				* taglib directive	: <%@ taglib page 속성명="속성값" ... %>
			
			- declaration 태그: <%! 자바코드 %> ( 서블릿의 인스턴스변수,  메서드 역할의 코드지정 자주 사용하지 않는다 )
			- scriptlet 태그	: <% 자바 코드 %> ( 서블릿의 doGet 역할의 코드 지정 )
			- expression 태그	: <%= 변수 %> ( 서블릿의 응답처리 역할의 코드 지정. 즉 웹브라우저에 출력됨 )

		다. EL ( Expression Language )
			
			문법: ${표현식}
			
		마. JSTL ( JSP Standard Tag Library )
		
			- 커스텀 태그 
				ex. 반복, 조건, ... 
					
					<c:if test=""></c:if>
					
4. 웹 어플리케이션을 개발하기 위한 방법 2가지
	
	1) Model 1 Architecture
		- 순수하게 모든 작업을 JSP로 처리하는 방식
		ex. 
			웹브라우저 <----> JSP ----> service ----> DAO ----> MySQL
		
		특징:
			- 짧은 시간안에 웹 어플리케이션 개발이 가능.
			- 관리에 많은 작업이 필요하다.
			- 현재는 사용안함. 
			
	2) Model 2 Architecture( MVC: Model View Controller ) (***)
		
		- 서블릿과 JSP 같이 사용하는 방식
		ex. 			
														Model(Data) - data처리
								Controller		|---------------------------|
			웹브라우저 ----> 서블릿 ----> service ----> DAO ----> MySQL
									|
									| 요청 위임
									|
						  <---- JSP(View) - 화면 구현
			
		- MVC(Model View Controller) 구조이다.
		- 서블릿은 Model과 View를 관리한다.
		- JSP가 클라이언트의 요청을 받을 순 있지만 항상 서블릿이 요청받게 작성해야 한다.
